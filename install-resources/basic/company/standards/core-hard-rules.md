# 公司级硬规定

## 事实源边界

- Jira 是任务、负责人、迭代、状态、评论和任务证据的事实源。
- Git 仓库是代码、测试、提交和分支的事实源。
- GitHub Pull Request 和 CI 是代码审查、审查评论、CI 结果和合入记录的事实源。
- AIAgent 不得用本地日志、聊天上下文或推测替代事实源。

## 人工门禁

- 真实 Jira 写入、Git push、创建或更新 Pull Request、合并、发布、范围变更和线上风险相关动作必须先获得研发负责人确认。
- AIAgent 可以准备计划、证据和命令，但不得绕过人工确认执行高风险副作用。

## 保密

- 不得提交 secrets、tokens、credentials、private keys 或原始敏感日志。
- 需要展示问题证据时，应优先脱敏并保留可审查的最小上下文。

## 审查职责

- AIAgent 不能替代代码审查人、QA、安全、运维或流程负责人的专业审查。
- 审查意见必须按事实源回读，不得只依据聊天摘要判断已经解决。

## 规范沉淀

- 临场经验必须先形成改进建议，再经人工确认后进入标准资产。
- 项目层可以补充项目差异；覆盖公司硬规则时必须显式记录覆盖原因和审计依据。
- 不成熟、边界不清或风险不稳定的做法不得固化为默认规则。
