## 执行、报告与修复

执行前核对工具链、测试资源、实际代码/Jar 与测试配置。使用目标工程已验证的原生命令；只有目录、插件和报告布局匹配时才复用 [Maven 模块执行工具](../../../runbooks/build-test-and-local-run.md#maven-模块选择执行与报告)。每条 Maven 命令先按该 Runbook 回读当前 run 的 `runtime/maven-local`，保留用户 settings 而不写共享本地仓库。未知入口报告缺口，不猜命令；先按目标工程入口编译新增用例并跑最小场景，失败优先读取被测任务日志、断言和实际加载依赖定位原因；不要直接全量运行掩埋首个失败。首次依赖未准备时不能机械使用离线参数，默认跳过集成测试的开关须按实际 POM 显式启用。

定向执行用于调试，完成后验证受影响模块的适用用例。保存实际命令、退出码、代码与用例版本、执行时间和报告引用；核对应测、实测和缺失范围。零用例、缺报告、跳过、超时或旧报告均不算通过。解析器支持实际格式时复用，退出码 0 不代替报告分析。主流程取得 PR 当前 Head 的运行与报告后，本技能按 [PR CI 报告回读](../../../runbooks/build-test-and-local-run.md#pr-ci-报告回读) 分析实际 checkout、run/attempt、用例和失败原因；Checks 成功不证明目标用例执行。其他 Checks 通过但无集成测试、未触发、跳过、零用例及缺报告时都返回具体仓库/Head/场景及原因，要求主流程取得研发明确处置；保留真实 NOT_RUN/SKIPPED/UNKNOWN，不能自行接受缺口或以已建 Jira 替代。

失败先归因，返回稳定 check_id 和归因证据。首次失败由主流程使用现有 failures.py observe 取得 problem_id；同一问题复发复用原 problem_id，核对累计轮次并 start 后才修复。当前变更导致的问题在授权内处理，修改后回传真实重验结果供主流程 finish。累计轮次及环境、已有失败、归因不明的处置沿用质量合同，不建立独立预算。网络只读故障有限重试并保留来源；外部写入结果未知交主流程先回读，不盲目重放。报告、源码或用例变化后重新核对适用性，不挑选成功 attempt，不把旧报告改写为新版本。

CI 问题修复并定向调试后，由主流程在授权内提交候选；本技能在完整提交 SHA 上完成最终本地验证，主流程据此 finish 并保存质量材料，再推送并等待新 CI。若已在工作区指纹上 finish 为 PASS，提交后需在真实重验通过后 revalidate，不能直接替换版本字段；失败仍按原问题记录。取得新 Head 的报告后再次分析，直至通过或到达具体人工处置点。Xray 关联 Test 由研发开发验证，不能用集成测试 PASS 替代。
