# TapData IT（Integration Test，集成测试）

TapData 代码变更以 IT为主要验证路径，依据 Wiki 规范和任务源码判断覆盖、编写及测试。TapTest（t-layer3-test）的用例开发与运行仅在用户选择当前会话处理时，由 [tapdata-task](../tapdata-task/SKILL.md) 导航至独立项目指引，不进入本技能的 Maven 流程。

分支适用性及提交边界遵循[分支修复与测试维护](../../runbooks/build-test-and-local-run.md#分支修复与测试维护)：IT集中在 develop 维护，其框架、用例和专用配置不回补低版本；普通 `test` 可随适用业务变更合入低版本，不因在 CI 执行而被排除；分析 release 时仍返回真实测试能力及覆盖缺口，不在 release 自动新增集成测试。需要 develop 修复或用例时返回主流程准备对应基线与授权，不自行切分支或借用 release 授权。业务与集成测试必须分开提交，develop 最终验证覆盖组合成果。

由 [tapdata-task](../tapdata-task/SKILL.md) 在方案分析、实现后验证和 PR CI 报告返回时按需调用，也可单独请求分析。先读取当前任务的范围、验收预期、工程基线和已有验证记录；实际源码取工位 source。无 current run 时仅输出“未绑定任务基线”的分析，不修改源码、不执行测试、不创建任务状态；仅有 Wiki 支撑的结论标为未核验。检测到 current run 后沿用主流程的授权、范围和失败记录，不借独立调用重置修复轮次。

本技能不推进阶段、不签发授权、不自行提交推送或创建 Jira 任务。主流程保有这些动作及质量记账；调用是同一 Agent 的职责切换，不要求另起任务或子代理。专项能力缺失只返回具体缺口，继续不依赖该能力的工作，不新增质量项或门禁。已有应测范围、用户选定验收项、PR Checks 和已登记失败仍遵守[质量检查与证据](../../../../docs/usage/quality-checkpoints.md)，不能通过漏报失败或缩减范围绕过。

## 按当前动作加载

只读取当前动作需要的资料；设计、执行、报告不是每次调用都必须重走的步骤。

| 当前请求 | 读取 | 返回 |
|---|---|---|
| 分析覆盖、判断框架或编写/修改用例 | [用例设计与编写](references/case-design.md) | 应测场景、实际源码/Wiki 依据、复用/新增/修改及缺口；有授权才修改 |
| 本地执行、报告分析或 CI 失败修复 | [执行、报告与修复](references/execution.md) | 实际版本、命令/报告、结果和归因；修改用例时再读设计资料 |

只分析报告时不自行重跑、改源码或推进主流程；失败修复必须复用主流程原 problem_id 和累计轮次，不重置预算。框架不支持（含当前全部 L3）返回主流程走 Manual Test 及兼容跟进，临时环境故障不能冒充框架缺失。其他 Checks 绿色不能证明目标 IT 执行；跳过、未触发、零用例或缺报告保持真实结果，交主流程取得具体处置。

## 返回主流程

按[测试编写缺口与 PR 总结](../../../../docs/usage/quality-checkpoints.md#测试编写缺口与-pr-总结)返回逐 scope/level 的 case_coverage 及逐用例完成和执行证据，区分已有覆盖、应写未写和已写未运行；框架支持而应写未写时补齐；不支持及当前所有 L3 返回手动路径和兼容 Jira 跟进要求，主流程复用现有验收项完成验证及关联回读，不用建票替代验证。返回本轮用例判断与依据、框架/环境可用性、实际改动、执行命令、源码/用例版本、应测/实测/未覆盖范围、报告及失败归因、下一动作。Wiki 依据仅引用文章路径及源码核验结论，遵守 tapdata-wiki 的输出约定。独立的只读分析请求只返回结果，不写任务记录或 Jira；仅在获授权的主流程中，由主流程将报告存入当前 run 的受控交互材料并引用到已有 verification/execute/failures 和 Jira 总结，不另建账本、不把技能完成写成任务验收通过。
