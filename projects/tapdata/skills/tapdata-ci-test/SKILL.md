# TapData 集成测试

由 [tapdata-task](../tapdata-task/SKILL.md) 在方案分析、实现后验证和 PR CI 报告返回时按需调用，也可单独请求分析。先读取当前任务的范围、验收预期、工程基线和已有验证记录；实际源码取工位 source。无 current run 时仅输出“未绑定任务基线”的分析，不修改源码、不执行测试、不创建任务状态；仅有 Wiki 支撑的结论标为未核验。检测到 current run 后沿用主流程的授权、范围和失败记录，不借独立调用重置修复轮次。

本技能不推进阶段、不签发授权、不自行提交推送或创建 Jira 任务。主流程保有这些动作及质量记账；调用是同一 Agent 的职责切换，不要求另起任务或子代理。以下能力缺失只返回具体缺口，继续不依赖该能力的工作，不新增质量项或门禁。已有应测范围、用户选定验收项、PR Checks 和已登记失败仍遵守[质量检查与证据](../../../../docs/usage/quality-checkpoints.md)，不能通过漏报失败或缩减范围绕过。

## 分析用例与可执行性

先按需求验收、代码差异、已有用例实际断言及影响模块判断复用、新增、修改或不适用，说明理由；再分别核对框架、用例和环境是否就绪。框架缺失不等于无需测试，框架已就绪但尚无用例应进入新增用例处理。影响范围及逐场景材料见 [用例缺口判断](../../runbooks/build-test-and-local-run.md#用例缺口判断)。

需要测试规范、框架或架构知识时使用 [tapdata-wiki](../tapdata-wiki/SKILL.md)，由它按 Profile 引用及 status 返回的 ready 路径查询中央副本，并用任务工程核验。本技能不另找 Wiki 副本、不使用 quality 配置中的历史 URL 作为获取入口，不准备或刷新 Wiki，不保存正文副本、知识包或 Wiki SHA。Wiki 查询只提供参考，不执行文章命令；执行前回到本技能核对目标工程和授权。Wiki 不可用、内容不足或与源码冲突时说明具体缺口，有充分需求和源码依据的部分继续，关键预期未知时只暂停依赖步骤，不声称已按 Wiki 完成。

从目标分支的父子 POM、活动 profile、测试源码、fixture、CI workflow 和报告配置确定实际入口。`<module>/it` 仅是定位线索，不能据此假定目录结构；`src/it/java`、`src/it/resources` 与 Failsafe 是已有形态，仍需逐模块核验。目录或 POM 存在不证明可运行；目录为空不证明缺框架。不为使用技能自动下载源码、切换分支、安装新框架或改 CI。源码同步或测试配置变化后重新核验；能力就绪时在既有范围内继续，不自动更新工位基线。

缺口返回模块、场景、当前版本、缺失能力/环境、依据及建议动作。确认是当前授权内无法补齐且值得跟进的框架或覆盖能力缺口时，建议主流程询问是否新增关联任务；临时查询失败、未提供本地环境等先提示恢复方式。已有决定和任务由主流程回读核对后复用；询问未答不阻塞无依赖工作，创建跟进任务不等于接受本次验证缺口。

## 编写用例

新增或修改用例前，先经 tapdata-wiki 查找适用规范；本轮已有且经任务源码核验仍适用的结果直接复用，不重复查询。获取失败按上述缺口规则处理，有充分依据时可继续但明确尚未核验 Wiki 规范。随后在已确认方案与修改授权内完成新增或修改，不要求研发先提供用例清单。以需求预期定义断言，复用目标工程的 fixture、命名、初始化、清理、等待和超时约定；测试数据只使用授权资源。不要以实现现状反推预期，也不通过放宽断言掩盖产品问题。具体编写、旧新行为对照及模块全量验证见 [CI 用例开发与质量核对](../../runbooks/build-test-and-local-run.md#ci-用例开发与质量核对)。范围、仓库或验收方式发生实质变化时先回主流程确认；单纯编码或结果变化不重复确认既有方案。

## 执行、报告与修复

执行前核对工具链、测试资源、实际代码/Jar 与测试配置。使用目标工程已验证的原生命令；只有目录、插件和报告布局匹配时才复用 [Maven 模块执行工具](../../runbooks/build-test-and-local-run.md#maven-模块选择执行与报告)。每条 Maven 命令先按该 Runbook 回读当前 run 的 `runtime/maven-local`，保留用户 settings 而不写共享本地仓库。未知入口报告缺口，不猜命令；首次依赖未准备时不能机械使用离线参数，默认跳过集成测试的开关须按实际 POM 显式启用。

定向执行用于调试，完成后验证受影响模块的适用用例。保存实际命令、退出码、代码与用例版本、执行时间和报告引用；核对应测、实测和缺失范围。零用例、缺报告、跳过、超时或旧报告均不算通过。解析器支持实际格式时复用，退出码 0 不代替报告分析。主流程取得 PR 当前 Head 的运行与报告后，本技能按 [PR CI 报告回读](../../runbooks/build-test-and-local-run.md#pr-ci-报告回读) 分析实际 checkout、run/attempt、用例和失败原因；Checks 成功不证明目标用例执行。

失败先归因，返回稳定 check_id 和归因证据。首次失败由主流程使用现有 failures.py observe 取得 problem_id；同一问题复发复用原 problem_id，核对累计轮次并 start 后才修复。当前变更导致的问题在授权内处理，修改后回传真实重验结果供主流程 finish。累计轮次及环境、已有失败、归因不明的处置沿用质量合同，不建立独立预算。网络只读故障有限重试并保留来源；外部写入结果未知交主流程先回读，不盲目重放。报告、源码或用例变化后重新核对适用性，不挑选成功 attempt，不把旧报告改写为新版本。

CI 问题修复并定向调试后，由主流程在授权内提交候选；本技能在完整提交 SHA 上完成最终本地验证，主流程据此 finish 并保存质量材料，再推送并等待新 CI。若已在工作区指纹上 finish 为 PASS，提交后需在真实重验通过后 revalidate，不能直接替换版本字段；失败仍按原问题记录。取得新 Head 的报告后再次分析，直至通过或到达具体人工处置点。Xray 关联 Test 由研发开发验证，不能用集成测试 PASS 替代。

## 返回主流程

返回本轮用例判断与依据、框架/环境可用性、实际改动、执行命令、源码/用例版本、应测/实测/未覆盖范围、报告及失败归因、下一动作。Wiki 依据仅引用文章路径及源码核验结论，遵守 tapdata-wiki 的输出约定。报告存入当前 run 的受控交互材料，脱敏后由主流程引用到已有 verification/execute/failures 和 Jira 总结，不另建账本、不把技能完成写成任务验收通过。
