# AIAgent 工作规则

## 1. 目的

本文定义 AIAgent 维护 AgenticOps 源头仓库时的工作规则，用于减少幻觉、提高效率并保护项目边界。

这些规则适用于 AgenticOps 文档、实现和维护阶段。第一个版本发布正式上线前的临时限制见 `docs/development-phase-rules.md`。

本文不等同于安装后 AIAgent 执行业务 Jira 任务的运行规范。安装后 AIAgent 的执行规范以 AI 员工手册、操作契约、工作流配置、运行资产、模板和对应运行文档为准。

## 2. 证据优先规则

AIAgent 做任何结论前必须先找证据。

有效证据包括：

- 当前仓库文件。
- `git status`、`find`、`rg`、`sed` 等命令输出。
- 已确认的项目规则和设计文档。
- 用户当前明确指令。
- 操作契约、工作流配置、AI 员工手册。

无效证据包括：

- 记忆中的模糊印象。
- 对 Jira 字段和流程的猜测。
- 对 GitHub 仓库结构的猜测。
- 对尚未实现代码能力的假设。

## 3. 禁止虚构能力

AIAgent 不得声称以下内容已经存在，除非当前仓库中有文件或命令输出证明：

- `agentic-cli` 已实现。
- `install.sh` 已存在。
- Operation YAML 已存在。
- 工作流配置可运行。
- Jira adapter 已可用。
- GitHub guard 已可用。
- Feedback command 已可用。

AIAgent 描述能力时必须以当前源码、测试和命令输出为准，不得把未实现内容表述为已完成能力。

## 4. 请求决策规则

当遇到以下情况时，AIAgent 必须请求用户决策：

- 文档目录结构存在两个以上合理方向，且选择会影响长期维护。
- 规则之间冲突，无法通过现有设计判断优先级。
- 需要决定是否把设计样例升级为运行时默认配置。
- 需要改变项目定位、事实源边界、安装目录或工作空间边界。
- 需要开始编码或生成可执行脚本。

如果只是补齐已确认方向下的缺失文档，不需要打断用户。

## 5. 范围控制规则

AIAgent 必须严格区分：

- AgenticOps 源头仓库资料。
- `~/.agentic-ops` 全局安装和配置资料。
- 项目 AI 工作空间资料。
- 具体任务执行产物。

不得把具体项目任务日志、代码变更、Jira 原文或敏感上下文写入 AgenticOps 全局资料。

## 6. 研发期临时门禁

第一个版本发布正式上线前，维护 AgenticOps 源头仓库的 AIAgent 必须遵守 `docs/development-phase-rules.md` 中的实现门禁。该门禁只约束正式上线前的研发期实现范围，不作为正式上线后的永久处理逻辑。

在人工确认和策略允许后写入 Jira 时，标题、描述、评论、工作日志、证据正文、阻塞说明和补卡说明必须使用中文；Jira 字段名、状态名、`transition` 名称和卡片编号可以保留原始值。

## 7. 输出纪律

AIAgent 输出应：

- 直接说明变更文件。
- 说明验证证据。
- 明确剩余未完成事项。
- 不夸大完成范围。
- 不把设计文档当成已实现能力。

## 8. 评审检查清单

每次完成文档变更前，AIAgent 必须检查：

- 新文档是否有清晰职责。
- 新文档是否被 README 或相关索引引用。
- 是否和 `docs/project-rules.md` 冲突。
- 是否和 `docs/architecture/agenticops-current-design.md` 冲突。
- 是否含有敏感信息。
- 是否出现未完成占位标记。
- 是否误导读者认为尚未实现的能力已经可用。
