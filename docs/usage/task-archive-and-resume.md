# 任务存档与恢复

本文现役命令继续按当前实现使用。[任务生命周期目标合同](../architecture/single-task-station.md#任务生命周期目标合同)定义完整目标；持久归档与[执行接管](../architecture/single-task-station.md#执行接管当前源码)已进入当前源码，两个清理范围已进入源码候选，仍须完整验收且不能当作旧安装已有能力。源码保留仍按工位合同区分当前实现；授权期限见[实施授权](task-authorization.md#实施授权)，旧安装不会因文档变化而更新。数据职责统一见[数据生命周期开发规范](../development-data-lifecycle.md)。

本文描述当前安装的存档与接续路径。任务档案记录已有状态和成果引用，未提交源码须独立保全，不能把引用当作源码备份；归档范围与缺项以[工位合同](../architecture/single-task-station.md)为准。更新后按功能发现差异、AI 修补并继续现任务的支持范围见[当前实现与限制](update-and-rollback.md#目标设计与当前实现)，不能将下文现役重建路径误认为永久开发要求。

恢复、清理与环境维护的职责见[生命周期协作规范](../maintenance-guide.md#生命周期协作规范)。先判断是恢复原 run/op，还是已退出后的成果接续；环境不健康不等于任务事实不可读取或代码工作不可继续；恢复部署、运行或测试仍须核验所依赖的环境。现役格式或 epoch 不被支持时，仍使用更新指引的当前路径。

任务处理到一半需要改进 AgenticOps、升级研发环境或重建工位时，可以保留已经确认的设计与代码成果，升级后从 Jira 任务继续。恢复入口是 Jira key；Jira 保存任务目标、决定和未完成事项，GitHub 保存已推送代码、PR 与 CI。工位本地存档用于保全材料，不能代替这些外部事实。

本文提供操作顺序和请求示例。授权与接续记录遵循[任务授权指引](task-authorization.md#从-jira-任务接续)，产品切换遵循[更新与回退](update-and-rollback.md#任务处理中升级后继续)，本地归档和清理语义以[工位合同](../architecture/single-task-station.md)为准。实际进度、阻塞和验收写入 Jira，不写入本文。

归档的本地副本按[工位合同](../architecture/single-task-station.md#8-脚本执行异常接力与恢复)尽力保存已核实的接续正文与 Jira 引用，不采集整个任务状态、配置或平台会话。归档缺项如实披露，写入失败按原操作处理，不能将缺项与写入失败混为一谈。原安装的行为须单独核验；原版读取或清理存在缺陷时，先保全并核验匹配版本的恢复候选，不以新版可启动或档案目录存在证明旧工位已退出。

请求移除工位时，应先核验本工位的任务与原清理操作，再按[退出合同](../architecture/single-task-station.md#8-脚本执行异常接力与恢复)展示任务退出及受管注销范围。结果分别说明归档覆盖、实际释放与注销；任务解绑与执行占用释放分开回读；finalizing 时可能已无当前任务，但执行占用仍保留，待收尾完成后才释放，不能从档案或错误退出码推断。缺陷处理结束应说明根因、具体修改、候选与实际安装版本及验证，设计修正不表述为代码已生效。

## 持久接续点操作

本节对应源码候选新增的持久归档入口，安装版本必须实际包含该能力并满足机器 epoch 合同；不代表旧安装已更新。本地尽力快照不能代替 Jira 接续点的回读证明。两个清理范围和执行接管的采用边界按工位合同核验。

Agent 先核实已有方案与实际进度，整理 JSON（不是要求研发填写表单）：`plan`、`progress`、`remaining`、`environment` 为必要文本；`evidence` 可提供必要材料的 `reference`（持久位置）、`source_ref`（原生回读来源）及 `local_file`（本轮取回的普通文件）对象列表；程序读取内容并保存摘要和大小，不把本机路径或材料正文写入归档；需放弃本次代码时 `discard_repositories` 按仓库记录明确决定来源，既不删除代码也不授权远端删除。未知外部操作须先回读，或在 `unresolved_operations` 按待办 kind 给出原操作、对象和回读线索。程序不能认证这些语义材料，Agent 仍需核对可信事实。

```sh
python3 <product-root>/workflow/station-clean.py --dir <station> --execute --action archive --handoff-input <材料.json>
```

程序检查保留代码的工作区、分支、历史基线及远端 Head；不会执行 commit/push。返回 `awaiting_jira`、稳定正文和内容摘要，保存原操作。Agent 用原生 Jira 工具查找相同摘要并回读；已有相同正文则复用，确认未写入且有授权才新增评论，未知结果禁止重发。正文包含可读取的方案、进度、代码引用与环境缺项，不含旧授权或阶段迁移数据。

将原生回读整理为 `site/issue_key/comment_id/body/source_ref`，原操作继续：

```sh
python3 <product-root>/workflow/station-clean.py --dir <station> --resume --operation-id <原操作> --jira-readback <回读.json>
```

尚未调用外部写入且决定取消时，同一回读文件可使用 `status=not_sent`、`decision_ref` 代替 `comment_id`，仍须绑定 site/issue_key/body/source_ref；这是明确未发送的决定，不是查不到评论就可推定未写入。取消不删除旧接续点；未核实发送结果时禁止改走清理。

只有对象与正文匹配才返回 `saved`、`storage=jira`。Jira 与 Git 无跨服务事务，不把部分保存当成整体成功；本地副本写入或格式异常时保留现场并明确警告，已核实的 Jira 接续点仍有效。原操作写回失败先回读再恢复；本地档案不是新工位的依赖。跨工位接续还须按[任务级接管协调](../architecture/single-task-station.md#jira-任务级接管协调与授权)核实交接；当前候选提供 coordination 入口，须主动提交原生回读；旧安装不会随指引更新获得该能力。

归档只覆盖正文对应成果，归档后新增变更须另存或明确放弃。

多次归档沿同一流程：有变化产生新摘要，无变化要求复用相同 Jira 评论；原生查重与回读由 Agent 执行，程序不隐式联网查询 Jira。失败的新点不取代上次有效点。恢复 Agent 从 Jira 选取最新可核实的有效正文；不同记录冲突时先解释事实，不能只按评论时间覆盖业务决定。

新工位核实正文中的 JSON 与摘要后，可提取既有接管输入：

```sh
python3 <product-root>/workflow/task.py handoff-continuations --dir <new-station> --input <正文中的JSON.json> --expected-digest <接续点摘要>
```

输出供现有 `takeover --continuation-input` 使用；缺失或变化的分支、历史基线与 Head 仍由接管入口核验。方案与进度通过下述所属接口接回为可核实成果来源，再由 Agent 按当前检查点补齐业务字段，不能直接赋值旧阶段。放弃的代码不进入续办输入；新工位重新配置环境并补齐剩余工作。同工位继续仍沿原 run/op。

接管与仓库登记完成后，Agent 从 Jira 核实最新有效决定，并原生取回必要材料，执行：

```sh
python3 <product-root>/workflow/task.py handoff-restore --dir <new-station> --input <正文中的JSON.json> --expected-digest <摘要> --expected-run-id <当前run> --expected-revision <当前revision> --source-ref <Jira回读来源> --decision-ref <有效成果确认来源> --evidence <材料回读列表.json>
```

没有必要材料时省略 `--evidence`。接口核对任务、源码分支和 Head、历史基线及必要材料内容，将方案、进度、剩余事项和环境要求保存到当前任务的 `facts.handoff_resume`，不导入旧阶段、授权或 PASS。Agent 使用正常项目入口复用仍有效的方案与验证、补齐环境及剩余工作；接口成功只表示成果来源已接回，不代表业务验证或部署完成。来源和确认由 Agent 核实，程序不认证 Jira 身份。格式版本和旧材料兼容边界见[归档恢复依赖描述](../../workflow/task-handoff.md)。

## 何时需要存档

同一个兼容版本、工位和运行仍有效时，直接恢复现有运行，通常不需要清理或重建。需要切换到不兼容版本、释放工位或丢弃当前执行现场时，先由原版本保存材料并退出，再创建新运行。跨多个版本使用同一顺序，不逐级转换旧状态。

先向 Agent 说明 Jira key、当前工位，以及希望保留或退出的范围。例如：

> 暂停 TAP-12345，保留已确认设计、当前分支和提交。核验 Jira 与 GitHub 上的接续信息，保全尚未上传的材料，再由当前版本归档清理并解绑这个工位。不要关闭 Jira 任务。

“结束旧运行”与“任务验收完成”不同。未完成的任务保持真实状态，不能为了升级将 Jira 改为完成或将历史报告记为当前通过。

## 升级前保存哪些信息

Agent 先从现有 Jira、GitHub 和源码推导已知事实，只补缺失内容，不要求使用者重新填一份交接表。

| 需要保留的内容 | 主要位置与核验方式 |
|---|---|
| 目标、验收标准、有效设计及最新决定 | Jira 任务字段和评论；发生冲突时说明来源并确认尚未确定的决定 |
| 仓库、工作分支、目标分支、历史基线和完整 Head | Jira 引用 GitHub 对象；核对远端提交和实际源码，不用最新目标分支替代历史基线 |
| 已完成验证、环境依据与未覆盖范围 | Jira 总结链接实际 CI、报告或附件；绑定对应源码版本，明确历史结果与本轮结果 |
| 下一步、阻塞、必要授权和待人工验收事项 | Jira 最新总结；区分已经确认的设计与需要重新建立的本版执行授权 |
| 未提交或未推送代码、仅本机存在的报告与配置 | 先核验并可靠保全；需要推送或上传时依当前授权执行，随后回读外部结果 |

秘密只记录文件或秘密管理引用，不把凭据、数据库 URI、原始敏感日志写进 Jira 或 Git。仅存在本机的备份须明确位置与恢复限制；机器丢失后，未上传材料不能保证取回。需要长期保存的成果应在授权范围内持久化到可访问的事实源。

旧版本记录不全时，Agent 可以读取可访问的旧会话、源码和报告，使用一次性脚本保全现场，再补齐 Jira。无法可靠核实的事实由 AI 向使用者提出具体缺项和选项，不猜测、不把整项工作默认重做。

## 原版本退出与隔离升级

Agent 使用绑定的原 Product Root 盘点当前任务、资源和未完成操作，按实际范围执行归档清理。按原版本的退出合同核验后执行 purge。需要保留进展时先完成持久归档；归档不解除任务。当前源码候选的任务清理在材料保全或明确放弃后删除 source，保留 config，清理完成才允许解绑；旧安装的源码和配置处置以原版本合同为准。残留或异常由 Agent 接手核实，不能把未完成清理当作成功。旧模式目标仍按其合同处理；当前功能校验模式不得仅因 epoch 差异要求退出，具体见更新指引。

共享安装还绑定其它活动工位时，升级该安装会影响所有绑定工位。只升级当前工位可使用以下请求：

> 仅处理当前工位：先由原版本存档清理并解绑，以同版本在 ~/agenticops-app 独立安装，按原版本实际保留结果复用配置或重新准备源码并绑定，再升级独立安装。列出并回读受影响路径，不改变原安装上的其它工位。

Agent 应先核验独立安装与原安装的产品提交一致，再按[更新与回退](update-and-rollback.md)切换目标版本、初始化并检查接线。source/config 可以按明确范围保留复用；旧运行状态、授权和质量日志不导入，新 runtime 不复制旧状态。旧档案保留在原 Product Root 的 `.archive/`，替换或删除该目录前须保全档案。

初始化与检查示例中的路径、项目和 Agent 由当前环境确定：

```sh
<product-root>/agenticops station init --station <station> --project <project> --reuse-materials
<product-root>/agenticops station doctor --station <station>
```

这些命令只完成工位生成与检查，不能证明业务任务、构建或应用已经恢复。

## 跨工位恢复的最小材料与缺项处理

恢复仅依赖 Jira 的有效方案、进度、剩余事项和远端 Git 的完整提交，以及确实不能再生成的外部材料；旧工位、旧源码缓存及 Product Root 的本地档案都不是前置条件。本地档案只作补充证据。Agent 归档前用原生工具实际取回必要材料并核对内容，按既有 evidence 引用记录远端位置、对象版本或摘要及回读来源；新工位再次核验。只存在链接文本不能宣称材料可恢复；不能保全的材料需明确披露并取得接受丢失的决定，不能让 AI 编造。

多次归档按内容摘要保留历史。接续先核对最新有效决定和远端事实；分支前进时不能把旧预期 Head 当当前 Head。继续新增成果，应核实差异后生成当前 continuation-input，保留真实历史基线，补充 Jira 接续事实；确需恢复历史保存点时，在授权后用原生 Git 将仍可取回的原 SHA 保全到独立远端分支，再用该分支接管，不回退原分支。远端对象不可取回时说明丢失范围，不能要求旧工位必然存在。

新工位重新配置秘密、环境和工具链；缺配置不阻塞独立代码分析，但运行及验证必须满足其输入要求。旧任务状态格式无法读取时保留原件并反馈维护面，优先在独立新工位从持久事实接续，不手改控制状态，也不把原状态修复成功作为新工位接管条件。辅助脚本不可用时由 Agent 读取 Jira/Git 并构造现有接管输入，仍由正常检查点验证，不新增通用迁移器。

## 从 Jira 恢复任务

在目标工位向 Agent 提供 Jira key 即可：

> 接续 TAP-12345。先从 Jira 与 GitHub核验有效设计、历史基线、保留分支和完整 Head，复用已完成成果；缺项先从源码和可访问材料补齐，仍不确定的再问我。使用当前版本接管，不导入旧授权或 PASS，并继续到实际可执行的下一步。

Agent 使用共享 [ao-task-resume](../../skills/shared/ao-task-resume/SKILL.md) 和当前项目任务技能：

1. 核验工位项目、绑定产品和占用；兼容且仍有效的运行沿原入口恢复，已退出或重建的工位建立新运行。
2. 从 Jira 读取最新事实，沿 GitHub 引用回读实际分支、提交、PR 和 CI，核验历史基线与预期 Head。
3. 用现役 `continuation-input` 与 `repository add` 入口续办既有分支；跨多个 epoch 仍使用这些输入，不解析旧运行格式。
4. 复用仍有效的设计决定，按当前检查点记录事实、证据与有效执行授权；范围或风险变化时仅补齐受影响决定。
5. 继续源码、验证及环境准备，写回 Jira 并回读；旧结果的适用性不明时保持待核验。

只有 Jira key 不代表所有历史材料一定齐全。远端分支缺失、历史基线不明、代码只存于旧机器或外部写入结果未知时，Agent 说明具体缺口，优先核实可访问材料；必要时由使用者补充仍缺的来源或决定。

## 恢复成功怎么看

分别核验以下成果，不能互相替代：

| 层次 | 应看到的实际结果 |
|---|---|
| 工位恢复 | 绑定正确 Product Root，doctor 通过；独立升级时其它工位未变化 |
| 代码恢复 | 工作分支、历史基线、完整 Head 和预期文件一致；保留提交可在 GitHub 或已核验材料中取回 |
| 任务恢复 | 当前运行能沿现役流程继续；设计和待办可从 Jira 获取，无旧授权或历史 PASS 被冒用 |
| 环境恢复 | 工具链、完整制品、数据库权限和秘密引用可用，实际组件健康及任务行为得到验证 |
| 任务验收 | 必要测试、审查、CI 和人工验收绑定本轮真实源码；按项目要求完成并回读 |

环境缺少构建、完整应用装配、数据库或许可证条件时，保留源码成果并继续不依赖这些条件的准备。Agent 应给出下一条可执行操作与明确缺项，记录实际 NOT_RUN/UNKNOWN；安装成功、容器创建或接管成功都不能冒充应用验收。

恢复总结至少说明已复用成果、新运行与实际阶段、当前源码版本、执行过的验证，以及下一步和剩余缺口。使用者之后再次给出同一 Jira key，Agent 应能沿这些已回读事实继续。

## 清理与成果更正

默认清理只删除已确认范围内的本地材料，不撤销 Jira 上的方案或历史成果。研发明确放弃已记录的实现或进度时，Agent 整理新的有效进度、保留方案及剩余事项，经确认后向清理入口提供 `--progress-correction-file <文本文件>`（task.py clean 的 JSON 输入使用 `progress_correction`）。说明不含秘密，不改 Jira 历史或自动设为完成。

本地成功与 Jira 更正独立报告。清理结果中的 progress_correction 提供稳定正文、摘要与目标；Agent 在本地清理完成后用原生工具查重、写入并回读，未知结果先查原操作，不能重发。回读的 site/issue_key/comment_id/body/source_ref 沿 `task.py cleanup-readback --operation-id <原清理编号> --input <回读.json> --dir <工位>` 核验。接口只收尾更正，不重新删除文件或取得任务接管权。

Jira 不可用时本地清理仍可完成，原有操作回执保留更正待办，后续新任务不抹掉它；本地清理完成不等于远端成果已更正。注销须先完成回读，避免删除唯一线索。旧版本不得继续写入带有待更正记录的新现场。此入口是已确认语义说明的回读，不自动判断哪些历史业务决定失效；恢复 Agent 仍核对 Jira 最新有效决定。
