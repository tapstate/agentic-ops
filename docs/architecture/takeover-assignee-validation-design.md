# 接管任务经办人校验设计

## 背景

`ao-work takeover <JIRA-KEY>` 当前已在接管前比较任务经办人与 Jira 当前账户，但测试只覆盖新接管的不一致情形，且没有明确证明失败前不存在 Jira 或本地任务状态副作用。未设置经办人与恢复、接纳存量任务也没有专项验证，造成实际环境难以判断是否已执行安全门禁。

## 决策

将经办人校验固化为三种接管模式共享的前置门禁：新接管、恢复与接纳存量任务都必须在创建或读取本地任务状态、写 Jira 评论、状态流转和 Git 相关动作之前完成校验。

- Jira `assignee` 缺失时失败关闭，并明确提示先按项目流程设置经办人。
- `assignee.accountId` 与 `/myself.accountId` 不一致时失败关闭，并提示切换正确研发员工作空间或调整经办人。
- 校验通过后保持既有接管、恢复与接纳流程，不新增人工确认。

## 实现范围

- 在 developer Runtime 的接管入口集中表达经办人前置校验及可诊断错误。
- 为三种接管模式补齐一致、不一致、未设置经办人测试；失败测试断言无 Jira 评论、无状态流转、无本地任务状态写入。
- 更新接管操作契约或手册，明确失败关闭边界。

## 非目标与风险

- 不改变 Jira 经办人，不引入自动改派。
- 不读取或输出 Token 等凭证。
- 不修改校验通过后的 Jira 状态映射、评论内容或 Git 流程。

风险仅为既有错误码或人可见文案更加具体；通过保持接管成功路径与固定验收回归控制兼容性。
