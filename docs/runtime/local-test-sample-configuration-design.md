# 本地测试样例配置设计

## 目标

统一 Tapdata FE 与 TM 的本地测试样例环境，并阻止 AIAgent 把仓库中的样例值直接当作真实运行配置。

## 已确认范围

- FE 与 TM 的 MongoDB 样例统一连接 `mongodb://mongo/tapdata`。
- TM 样例不设置 `TAPDATA_TM_ID`。
- `app_type=DAAS` 继续作为 FE 与 TM 的共同样例配置。
- FE 的 `backend_url`、TM 的端口以及所有 MongoDB URI 在真实启动前必须由用户修改或逐项确认。
- 未完成确认时，AIAgent 必须停止在配置确认阶段，不得启动 FE 或 TM。

## 方案选择

采用“运行手册保留统一样例，并声明运行前确认门禁”的方案。

未采用以下方案：

- 不把这些值加入项目工作流配置。它们属于本机和任务级运行参数，不是跨用户稳定的项目默认值。
- 不把确认逻辑固化到 `agentic-cli`。当前 CLI 不负责启动 FE 或 TM，缺少稳定的原子操作边界。
- 不删除全部具体样例。保留可运行结构有助于用户识别需要提供的参数，但样例值必须和真实配置明确区分。

## 运行规则

运行手册必须明确区分两层内容：

1. 样例配置：只展示变量结构和一组内部一致的参考值。
2. 已确认配置：用户针对当前工作空间和当前任务修改或确认后的实际值。

AIAgent 准备启动 FE 或 TM 时，应向用户展示当前拟使用的配置，至少确认：

- FE 与 TM 是否连接同一个 MongoDB 环境。
- FE `backend_url` 是否指向本次启动的 TM API。
- TM HTTP 和 WebSocket 端口是否可用且不会与其它实例冲突。
- 工作目录是否适用于当前工作空间。

确认结果只用于当前任务执行和证据，不应反向改写仓库样例、项目默认策略或共享配置。

## 验证

- 检查 FE 与 TM 样例中的 MongoDB URI 都使用 `mongodb://mongo/tapdata`。
- 检查 TM 样例不再包含 `TAPDATA_TM_ID`。
- 检查手册明确写出未确认配置不得启动。
- 更新安装资源校验和并执行资源测试。
