# 数据生命周期开发规范

## 职责与适用状态

本文是数据分类、作用、生命周期和功能管理责任的唯一开发规范，适用于新增或修改的功能。它与[确定性执行与 AI 接续原则](maintenance-guide.md#确定性执行与-ai-接续原则)共同约束实现，不代表现有功能已完成改造。操作行为由[工位合同](architecture/single-task-station.md#任务生命周期目标合同)定义，验收由[PROD-003](user-stories/v1/prod-003-multi-repository-task.md#目标用户故事)维护；项目指引只维护具体配置、资源与构建方法。不新增执行计划、数据分类平台或平行任务台账。

## 数据分类与生命周期

| 类别及作用 | 写入与存放 | 保全与恢复 | 生命周期终点 |
|---|---|---|---|
| 任务成果：需求方案、决定、实际进度、剩余事项 | Jira 是持久事实源，本地只存执行所需状态；正常协作节点持续回写 | 归档核实持久结果，恢复据实建立当前状态，不能只同步 Jira 状态名 | 清理删除本地副本，保留 Jira 历史；放弃成果须纠正可恢复进度，不抹除历史 |
| 源码成果：实现及可版本化材料 | 工位 `source`；保留成果进入远端 Git | 记录仓库、分支、目标分支及完整提交，回读确认推送；新工位取回核实 | 保全或明确放弃后删除本地源码；远端分支、PR 和合并结果独立处置 |
| 必要证据与不可再生数据：验证依据、唯一样本等 | 由产生功能明确位置，可靠外部存储承担持久保存 | 归档保存内容或复用可靠来源并记录引用；引用存在不证明内容可取回 | 可靠副本已确认或用户明确接受丢失后，才可删除唯一的本地材料 |
| 用户配置、草稿与秘密：可复用环境输入 | `config` 或外部配置/秘密服务；不能只存在于 `source`、`runtime` | 归档说明环境要求、缺项和获取方式；新工位由 Agent 与研发补齐，无法重新取得的材料另行安全保全；秘密不写 Jira 或普通档案 | 清理任务保留；清理工位删除工位内材料，不撤销外部秘密或删除共享配置 |
| 可再生及临时数据：构建产物、依赖副本、缓存、普通日志 | `source` 或 `runtime`，与持久配置分离 | 默认不归档，按需重建；成为必要证据时先按证据类保全 | 相关写入停止后随清理删除 |
| 工位基础信息：身份、登记、受管接线 | 初始化管理的 `.agenticops` 与接线文件 | 不作为任务成果迁移，由当前版本初始化能力维护 | 清理任务保留，清理工位保留或恢复到当前版本初始状态；注销另行处理 |
| 执行协调数据：接管占用、任务控制状态、在途操作及清理回执 | 统一流程状态入口，不由各功能另建状态目录 | 同工位沿原操作恢复；跨工位不复制锁、旧授权凭据或 PASS；未知外部操作结果记录对象并先回读 | 资源处置和结果核验结束后再清除必要恢复记录，不能先删身份再找资源 |

分类是语义约定，目录是落实手段。普通文件通过区域决定生命周期，不逐文件注册；同一区域出现持久材料时，创建功能必须先提供保全路径。不可再生数据不能承诺由 AI 重新生成。工位中未知内容不能仅凭所在目录推定已获放弃授权；清理工位可在明确展示范围并取得整体丢弃决定后处理工位内用户数据。

## 功能的管理责任

功能设计必须说明实际产生的数据属于哪一类、写在哪里、如何保全和恢复、何时可清除；在已有设计与项目指引中记录差异，不要求另填统一表单。正常写入遵守区域约定，任务控制数据沿现有受支持入口变更。新功能通常不应修改公共清理主流程。

进程、容器、网络、数据卷等是运行资源，与其中的数据分别判定。创建功能负责可核验归属、独占或共享关系、发现、停止、释放及回读；优先复用路径、原生标签与已有记录，不新建资源注册平台。创建中断仍可发现残留，资源已不存在可重复收尾。本地目录丢失不代表外部资源不存在。释放只依赖身份、处置授权与实际停写，不依赖构建成功、部署健康、完整业务配置或任务已解绑。

任务清理组合资源收尾，收尾不得反向调用任务清理；遵循已有锁顺序，不在持锁状态再次进入同一顶层命令。公共清理负责范围、安全删除和结果汇总，不解释业务文件、不猜资源价值，不允许清单携带任意执行脚本。共享服务、公共镜像和缓存不因任务退出删除。新增资源类型仅补必要的释放能力，不建设插件框架。

修改写入位置或删除功能时，必须交代旧数据和旧资源的识别、保全及处置，在移除收尾能力前完成处置或提供足以由 Agent 核实处理的信息。不永久保留旧版功能只为清理，不添加逐版本清理/迁移脚本。旧输入不符沿外部依赖规范发现、修补和复查；同版本自产合法状态自阻塞属于程序缺陷。

## 环境维护与验证

编译装配按源码、依赖、配方与平台核验输入，仅复用仍有效的产物。可独立完成的构建及预检先于停止旧部署；运行实例直接消费构建输出时须隔离输出或取得停用决定，不能保证任何编译失败都零影响。部署切换中断回读实际现场，不自动回滚数据库；恢复代码工作不以应用健康为前提，运行和测试仍检查所需环境。

通用闭环与接力验收引用[功能逻辑闭环验收](maintenance-guide.md#功能逻辑闭环验收)；本规范补充数据特有的目录丢失、保全、重复收尾和共享资源保护场景。清理记录最后处理；残留必须如实披露。完整用户故事见 PROD-003，不重复建设验收器。源码重建须测量真实项目的热缓存耗时、远端传输和后续依赖/编译成本，不以源码池存在证明重建免费。
