# PROD-001 安装并接入多种 Agent

研发工程师安装指定分支的产品资产，通过 Manifest 接入一个或多个 Agent；工位同一时间只处理一个任务，每任务可以修改多个仓库，多个工位承担并发。

### 验收标准

- macOS、Linux 使用 Git 和 Python 3.9+ 即可安装、更新和回退。
- 中央产品根目录（Product Root）保存唯一运行资产；源码目录和安装产品根目录使用同一入口和产品结构。
- 生成单工位 config/source/runtime 和空 current，并由 Product Root `.archive/` 保存正式档案；源码池由产品根自动管理，仅加速接管时的独立源码下载。purge 验证空闲、已完成操作和生成归属，保留持久材料及中央档案，再生成需显式复用决定。
- 工位使用 `.agenticops/` 保存初始化与唯一当前任务；config/source/runtime 分离持久材料与运行现场，不复制 Project Skill、Policy 或 Runtime。
- Manifest v3 声明原生指引、启动方式、Skill 和退役产物；新增 Agent 无需工具 Hook 入口，不生成通用工具拦截接线。
- 共享 Skill 按[维护规范](../../skill-maintenance.md)在源码维护根与项目工位发现；维护 Skill 不进入安装或业务工位，共享方法根据目标项目读取事实，不要求活动任务。
- Agent 在同一工位会话继续任务；上下文验证 source 独立仓库，不扩展其它工位权限。
- `agenticops station doctor` 发现产品版本和薄接线漂移，`agenticops station repair` 重建派生接线，不修改任务状态和授权；同名非产品文件必须拒绝覆盖或删除。

### 保护行为

- 安装只检出产品目录，不包含 `internal/`、仓库发布脚本和发布凭据。
- Agent 适配器不得复制 Policy、任务状态机或项目规则。
- 适配器必须通过声明式文件边界、禁止执行器、禁止依赖和禁止状态写入检查。

### 升级恢复目标验收

以下验证[工位合同的目标设计](../../architecture/single-task-station.md)，不代表原安装已应用或原工位已恢复。采用临时真实 Git 安装及工位夹具，模拟不能替代原版本现场恢复和新版接管证据。

| 场景 | 必须观察到的结果 |
|---|---|
| 请求移除但原清理未完成 | 一次明确展示剩余任务退出及 purge 范围，复用仍有效的真实决定；原操作未结束拒绝 purge，成功后核验受管接线/状态与索引注销且 source/config/档案保留，不声称工程目录已删除 |
| 原版可正常退出 | 直接退出/purge 后升级；不要求额外中间更新 |
| 远端 tip 已跨 epoch，原通道历史有适用兼容补丁 | 完整 SHA 定点更新仍在原通道内，旧请求与原操作可恢复，正式归档、clean/release、purge、新版 init/Jira 接续逐项核验 |
| 补丁仅在原版本维护分支 | 普通 update 拒绝越出通道；明确 recover-install 仅接受同 origin、已核验同 epoch 的向前补丁；退出后干净安装新版，保留旧档案和 source/config，不强行合并或重写历史 |
| 首次旧入口不支持新参数 | 经审查原版本候选中的同一 Bootstrap 实现可显式指向旧安装；配置格式不支持时拒绝，不用复制覆盖或修改状态补偿 |
| 选择了最新同 epoch 提交，但没有对应退出修复证据 | 不能宣称可退出；不自动归档或跨 epoch 切换，保全并继续核验 |
| 两个工位共享安装，单独 archive、空闲未 purge 或只有一个退出 | 旧模式目标跨 epoch 更新仍拒绝；功能校验模式须核实全部工位停写及在途操作。只授权一个工位时不得擅自切换共享安装 |
| 原安装脏树、HEAD/记录不符、远端或目标不符、引用不可达、历史不足，或维护恢复的目标与原版本 epoch 不同 | 初次执行拒绝，保留原修改与状态；恢复及跨 epoch 时登记缺失/损坏拒绝；目标重读后变化不沿用旧决定 |
| 产品调用仍运行或无法核验停写 | 生命周期锁不冒充已终止旧进程；产品切换暂停，不扩大业务资源处置 |
| 范围准备、HEAD 切换、产品记录或版本提示写入中断 | 原/目标 SHA 绑定的有限组合可按同一实现续接；第三值、非法顺序和证据不符拒绝；重复调用不覆盖 previous_ref，不重做任务清理 |
| 同 epoch 接线刷新、旧版退出及新版接管 | 旧状态、确认、授权和档案含义保持；新版不继承旧授权，真实退出和新接管分别验收 |

原版本补丁单独回归旧默认、旧请求、未发布草稿、正式档案不可变和原操作修订/中断恢复；生命周期能力不改工位状态字段或提升 epoch。运行代码候选按既有 affected staged 选择器正式验收，Bootstrap 和共享入口变更回到完整四项；macOS/Linux、Python 3.9+ 和默认 update/rollback 均需回归，无新增第三方依赖。

### 验收证据

- 产品稀疏安装、中央入口、项目工位初始化、漂移诊断和幂等修复结果。
- 更新到新提交、工作目录刷新并回退到上一提交的测试结果。
- 共享技能同源、同名冲突、旧清单补齐及漂移保护、旧安装资源补齐、重复更新保持回退指针、回退移除共享接线的结果；用户级目录保持未写入。
- 无 Python Hook 的第三方 Agent Manifest 发现、产物生成和启动结果；原生 MCP 与 Skill 接线回归。
- 同版生成→任务退出→purge→生成、持久材料复用、新工位身份与旧状态拒绝测试结果。

### 新任务前更新目标验收

本节验收[更新选择合同](../../usage/update-and-rollback.md#新任务前检查与更新目标设计)与[产品互斥设计](../../architecture/agenticops-v1-architecture.md#产品调用与版本切换互斥目标设计)。实现候选的逐项证据记录在 Jira，不能因入口已接入而推定本表全部通过。测试使用隔离安装、两个真实工位与临时 Git 远端，不在用户共享安装上注入故障。并发用父子进程管道/事件屏障控制先后，不依赖 sleep 猜测。

| 场景与输入 | 必须观察到的结果 |
|---|---|
| 工位 A 调用在加载模块前、工位锁内、延迟导入或子进程运行时暂停，B 发起兼容更新 | 独占尝试返回忙碌，HEAD/产品记录不变；A 完成后 B 才可切换；读命令与 Project 脚本也覆盖 |
| 更新持独占锁暂停，两个工位发起产品调用 | 两者均不能加载旧产品模块或写状态；恢复后重新核验并加载实际版本，不混用新旧模块 |
| 两工位同时新接管并发现同一新版 | 仅一次切换，其它请求重新核验；previous_ref 不重复覆盖，各工位 run/op 独立 |
| 当前调用共享租约与工位锁已持有时请求更新；生命周期内部 repair/purge 产生子进程 | 不原地升级锁、不死锁、不通过环境变量跳过校验；内部复用仅在真实父租约下有效 |
| 会话工具调用间空闲、但会话仍使用旧 Skill | 会话租约仍阻止自动切换；退出或经验证的暂停后才放行；后台子进程不能泄漏租约或提前失去保护 |
| 锁持有进程异常退出、文件残留或外部替换 | 正常退出/异常退出释放内核锁；正常操作不删除稳定锁文件；身份漂移拒绝切换，不抢删仍有效锁 |
| 跟踪分支同 SHA、快进同 epoch（含原安装位于合并第二父链）、不同 epoch 目标 | 分别无更新、满足独立切换条件时可更新；不同 epoch 的功能校验目标不单独阻塞，仅旧模式不兼容目标进入选择；兼容判定遵循工位合同，其它分支/Tag 不改变判断 |
| 不兼容或其它会话忙碌，用户选择旧版 | 当前安装和其它工位不变，接管水印为实际旧版；不持久关闭后续检查、不重复询问本次有效决定 |
| 目标材料缺失、网络超时、清单损坏、dirty、分叉、HEAD/记录漂移 | 区分检查不可用、目标未知和本地不可信；不宣称最新、不覆盖本地改动；可继续条件符合更新选择合同 |
| 检查后目标/epoch/登记/工位绑定改变 | 应用前重新核验；不沿用扩大范围的旧决定，不以预检成功代替实际更新 |
| 产品切换、范围刷新、版本记录、repair 或会话生效各阶段失败 | 回读已完成结果，未满足闭环不创建新 run；按现有原/目标绑定恢复，不自动回退或重新清理 |
| 两工位共享旧安装，仅对 A 独立安装并重建 | B 的产品版本、任务及绑定不变；A 经原版 purge/新版 init 保留 source/config，旧档案保留，不继承旧状态或授权 |
| 当前任务未完成、原 run 或在途 takeover 恢复 | 恢复不触发自动切换，不新建 run 伪装重试；需要跨 epoch 时先保全，按目标兼容模式选择原 run 接续或原版退出，不要求 Jira 完成 |
| 旧客户端首次采用、未受管桌面会话、回退至不支持租约版本 | 不能以新锁空闲推断停写；保留手工核验或独立安装路径，不宣称追溯保护 |

实现验收先证明旧竞争窗口可重现，再证明修复后两个方向均互斥，覆盖 macOS/Linux 与 Python 3.9+，无第三方依赖。直接 Python、shell 生命周期、Agent 启动、Project 脚本须列出实际入口覆盖证据；任一入口缺失不得宣称共享自动更新安全。标准库文件锁原语实验只能证明机制可行，不代表入口集成、首次采用或会话重载通过。

真实平台验收分别覆盖 Codex 与 Claude 的受管启动和桌面手工进入：明确哪些可自动继续、哪些需要新会话，在目标工位实际发现并读取新增/删除/改名后的技能与规则后接管；磁盘接线或启动退出码不能代替此证据。实现候选按 `internal/acceptance.sh affected --change-source staged` 正式验收，选择器涉及安装与共享入口时执行完整四项；真实安装、平台和发布证据与本地模拟分别记录在 Jira。

### 活动任务更新选择

启动原任务也探测新版，但探测和选择不修改 run、阶段、源码或在途操作。研发明确选择继续旧版时可启动；确认原/目标 SHA、登记范围并核实停写后才更新。仅提供停写声明不触发更新；版本或登记范围变化使旧确认失效。功能校验目标跨 epoch 沿相同路径，当前任务内容保持；异常和旧操作采用由所属功能合同检查，不宣称任意历史语义都已转换。
