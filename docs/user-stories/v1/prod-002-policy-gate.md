# PROD-002 执行确定性流程检查点

Agent 使用原生工具执行任务；Workflow 在实际状态变更处按项目规则检查准入、方案确认与验证证据。保证边界以[项目目标](../../strategy/project-goals.md)和[架构](../../architecture/agenticops-v1-architecture.md)为准。

### 验收标准

- 阶段推进绑定 issue、run 和预期阶段；重复或过期调用不能推进到另一个阶段。
- 本地状态读改写持有工作空间任务锁；失败不把阶段、确认或证据标记为成功。
- 方案确认在进入实现及后续验收检查点重新校验 run、仓库、范围、基线和验证方式。
- 新工作空间不生成通用 Agent Hook；Git/Jira/PR 和普通本地工具使用平台原生权限。
- 旧工作空间通过显式迁移移除已核验归属的旧 Hook；start、普通 repair 与刷新失败关闭且保留现场，修改过的旧 Hook 不得覆盖或删除。
- Jira 同步准备和回读不改变本地阶段，不宣称外部调用被强制限制为一次。

### 保护行为

- 状态门禁不等于任意工具副作用前的阻断；合并、发布等仍需要独立授权与服务端保护。
- 旧 run 的写入不能覆盖新 run；状态确认记录不提供用户身份认证。
- Agent Adapter 不保存状态或项目规则；源码仓库 Git Hook 保持独立。

### 验收证据

- 重复推进、旧 run、并发状态写入、确认绑定漂移与缺失证据的失败测试。
- 全新安装、旧 Hook 显式迁移、漂移保留以及 start/doctor/repair 回归。
- 原生工具无自动 Gate 接线，Jira 结果未知不伪造成功。
