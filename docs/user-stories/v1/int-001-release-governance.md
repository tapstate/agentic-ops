# INT-001 审查并发布 AgenticOps

项目维护者在 `develop` 形成经过影响范围验收的候选，通过代码审查后发布到 `main`。内部治理工具只服务 AgenticOps 仓库，不构成第二套产品 Runtime。

### 验收标准

- 普通提交/PR 候选按确定性影响范围验收，至少运行资源边界；共享实现、契约、安装、门禁及无法可靠映射的变更回到 Runtime、Resources、Install、Release 完整四项。发布直接复用同树、同合同、同环境的完整四项开发验收；没有有效结果才隔离补验，结果跨准备、发布与恢复复用，不把每次入口调用当作重验；故事注册表在 Runtime 内覆盖，不另作为第五项重复执行。诊断检查不生成提交放行证据。
- 验收证据 v6 绑定完整候选树、精确比较基线、变更范围、选择器内容摘要、最低检查集合、实际执行集合及可移植环境事实。staged 验收前后工作树必须与索引一致，range 必须实际检出指定 Head；漂移不能通过。
- `main`、版本 Tag 和发布写入只通过版本化发布流程完成。合并前固定发布方式、版本（如需要）、目标基线与候选；合并后核验实际双父提交和完整树，漂移不得借用旧验证结果发布。
- 信任根 Hotfix 走人工审查 PR，无版本 Tag；epoch 不决定发布方式。正常与恢复均明确区分已交付和 develop 同步待办，保留并行开发提交。

### 发布主线验收场景

- 正式发布与 Hotfix 都在 develop 确定候选并取得有效完整四项结果，通过后创建 develop → main PR；没有 PR 的 main 直推和自动合并均不属于发布入口。
- prepare 只生成验收证据，不创建 release 分支；不依赖远端同步、main 集成、Tag/存档可用性、Auto-merge 或 main 保护配置，不推送、不修改仓库设置。重复准备相同候选复用有效结果，显式 verify 才重验。
- 验收从 staged 形成 commit、修改版本/Jira 或同树基线变化可复用，不执行测试；树、合同、环境变化及不完整/失败记录不能冒充完整通过。显式重验失败后不能回退旧开发结果；时间以实际时刻比较，同一时刻冲突和坏时间不能误选通过，开发验收进行中不能消费旧通过。
- 提交审查复用有效完整四项证据和明确操作授权，不额外要求开发台账。缺少确认、证据失效、main 基线或 develop/PR Head 漂移时不得沿用旧批准交付。
- PR 返工需重新核验候选和取得新范围确认，复用原 PR 更新受管证据，保留人工文字；无有效新证据或确认时不推送。原交付身份可跨分页查询，不把历史记录遗漏当作新发布。
- 完整发布合并后，Tag 与 release/v* 存档都指向同一实际 main Merge commit。已有正确对象可复用，Tag 已写而存档失败可重试补齐；任一引用冲突不覆盖，不能报告完成。
- Hotfix 无论 epoch 或信任根是否变化，均经 PR 合并；完成后没有版本 Tag 或 release 存档。本地验证允许仅给 Jira，合并后收尾缺证据时停止，不隐式重验；显式按原 PR 补验后继续。
- main 保护和未解决审查异议仍需核验；单人维护没有另一账号 APPROVED 不自阻塞，草稿审查不参与已提交意见排序，无异议也不能冒充人工批准。
- develop 后续前进时，已合并 PR 按原 Head 和实际合并提交收尾，不改换候选；同步 develop 不能覆盖并行提交。
- 旧 release 候选与新存档同名不阻塞 prepare 或 PR 审查；创建存档时停止并说明需人工处置，不为兼容自动移动历史分支或修改原 PR 绑定。显式授权迁移只接纳原 release PR Head，必须先保全并回读旧候选，再补 Tag、快进至原合并提交；引用漂移拒绝，失败保留成果，重试不改 Tag、不重复验收。

操作入口和现役边界唯一见[维护指引](../../maintenance-guide.md#6-发布与-hotfix)。

### 保护行为

- `internal/` 不进入研发安装目录，也不被业务 Agent 加载。
- 候选修改门禁实现时不能用未暂存代码替代受审查内容。
- 正式重验立即撤销旧通过结果与同候选审批；稳定锁覆盖完整执行和进程回收。失败、取消、超时不会恢复旧通过。每次运行独立保留日志，消费的摘要自包含计划检查集合、实际结果、验收范围与日志摘要；局部结果不能冒充完整验收。
- v3/v4/v5 证据保留查阅，不满足 v6 选择与候选绑定合同，不双写或伪装旧格式。首次升级通过受保护 main 的人工审查 PR；旧发布门禁拒绝 v6 为预期，不增加旁路。发布复用完整开发测试事实，不沿用其审批；代码验证结果的复用、失效及恢复遵循[维护指引](../../maintenance-guide.md#发布验证复用与合并后收尾)。
- Agent Hook、共享 Adapter Runtime 或 Tool Adapter 分类策略变化时，自动发布失败关闭，只能通过受保护 `main` 的人工审查 PR 升级信任根。
- 本次 v1 重构允许删除旧 `developer/`、`maintainer/` 和 `shared/` 资产；这些路径后续重新出现时仍进入内部治理并由资源合同拒绝。

### 验收证据

- 按影响范围或完整验收的计划与结果、候选提交和代码审查事实。
- 发布后 `main`、`develop`、Tag 与 release 存档（正式版本）指向回读；Hotfix 不生成 Tag 或版本存档。验收覆盖有效证据下合并后零次完整重验、失败后旧证据失效、未知写入回读、源分支删除恢复及并行 develop 的准确待办。

### Python 运行环境验收

- 开发验收与发布统一 Python 3.12.x，选定解释器贯穿子进程和证据；同树同环境复用原验收，真实版本变化仍失效，不借助 uv 前置 PATH 隐式切换。
