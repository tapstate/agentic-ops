# INT-001 审查并发布 AgenticOps

项目维护者在 `develop` 形成经过固定验证的候选，通过代码审查后发布到 `main`。内部治理工具只服务 AgenticOps 仓库，不构成第二套产品 Runtime。

### 验收标准

- 正式验收固定执行 Runtime、Resources、Install、Release 四项各一次；故事注册表在 Runtime 内覆盖，不另作为第五项重复执行。诊断检查不生成提交放行证据。
- 验收证据 v5 绑定完整候选树、精确比较基线、变更范围、验收合同和可移植环境事实。staged 验收前后工作树必须与索引一致，range 必须实际检出指定 Head；漂移不能通过。
- `main`、版本 Tag 和发布写入只通过版本化发布流程完成。

### 保护行为

- `internal/` 不进入研发安装目录，也不被业务 Agent 加载。
- 候选修改门禁实现时不能用未暂存代码替代受审查内容。
- 正式重验立即撤销旧通过结果与同候选审批；稳定锁覆盖完整执行和进程回收。失败、取消、超时不会恢复旧通过。每次运行独立保留日志，消费的摘要自包含四项结果与日志摘要。
- 新版不采信 v3/v4 证据为完整四项验收，不双写或伪装旧格式。首次升级通过受保护 main 的独立人工 PR；旧发布门禁拒绝 v5 为预期，不增加旁路。发布随后仍独立执行隔离环境四项验收，不消费开发结果代替发布验证。
- Agent Hook、共享 Adapter Runtime 或 Tool Adapter 分类策略变化时，自动发布失败关闭，只能通过受保护 `main` 的独立人工审查 PR 升级信任根。
- 本次 v1 重构允许删除旧 `developer/`、`maintainer/` 和 `shared/` 资产；这些路径后续重新出现时仍进入内部治理并由资源合同拒绝。

### 验收证据

- 固定验证、候选提交和代码审查事实。
- 发布后 `main`、`develop` 和 Tag 指向回读。
