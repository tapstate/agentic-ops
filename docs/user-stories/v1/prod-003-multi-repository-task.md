# PROD-003 推进并恢复多仓库研发任务

一个项目工作空间可以同时接管该项目下多个 Jira 任务，每个任务可以绑定多个 Git 仓库；Agent 中断后从各自阶段和 pending 原因恢复，并汇总各仓 PR、CI 与验证证据。

### 验收标准

- 阶段不可跳跃；准入按项目规则核对，缺少授权或可靠仓库基线会阻断受影响步骤。启用质量处置模式时，普通缺项先披露，推进检查点必须有用户处置记录，不要求所有测试全绿。
- 检查点包含多个检查项，每项绑定一个用例和一种验证方式；修复前后项分阶段到期，原始执行结果、用户选择和风险处置独立保存，具体操作见[质量检查与证据](../../usage/quality-checkpoints.md)。
- `.agenticops/tasks/index.json` 统一注册多个任务及 active/inactive/completed 状态，任务事实、授权、事件和 CI 记录按 issue key 隔离。
- 多个任务可同时 active；Workflow 显式绑定 issue key，Hook 按 Jira 任务号或仓库与工作分支唯一解析，歧义时失败关闭。
- 一个授权绑定多个仓库，每仓独立校验 origin、分支、范围和验证方式。
- 多个工作空间共享 `<pool>/<owner>/<repo>` 主工作树；任务修改只落在 `<workspace>/.agenticops/worktrees/<issue-key>/<run-id>/<owner>/<repo>`，准备前同步远端并固化 `base_sha`。
- 同 run 恢复幂等；reset 创建新 run。清理拒绝脏 worktree，并与工作空间 purge 联动。
- 缺陷接管成功后同步尝试一次 `In Progress`，Q4 验收完成后同步尝试一次 `Tests Passed`；已达目标直接记录，其它状态、必填字段不足或外部失败均记录并跳过，不阻断本地主流程，也不自动执行 `Pull Request Submitted`。
- PR Ready 前核对 Jira 关联测试任务全部完成、当前 PR Head 的 Checks 全部明确成功，以及 Q1-Q4 和其检查项全部通过或明确不适用；三类事实分别保留来源和具体待办。

### 保护行为

- 新增仓库或修改稳定绑定后旧授权失效。
- 主工作树、其它任务 worktree 和整个 Source Pool 不进入当前任务 Agent 的可写目录。
- 本地任务分支默认保留；显式删除只使用安全的 `git branch -d`，残留分支不静默复用。
- PR/CI 结果不改变授权指纹；合并和发布不被任务授权覆盖。
- Jira 状态转换只有在当前 task/run 已准备精确 transition 意图时才能自动放行；转换后必须回读。状态同步意图每个节点只准备一次，失败不能阻断本地推进或被伪装成成功。
- 质量确认绑定对应计划、代码及证据；内容变化使受影响确认失效。旧 run、其它仓库的同号 PR、跳过或未知结果不能冒充当前用例通过；风险处置不能代替安全授权或 Jira Validator。
- 外部评论须先持久记录已确认草稿的写入意图；回执不明先核对，回读匹配后才能确认发送结果。记录损坏及并发旧 revision 保留现场并拒绝覆盖。

### 验收证据

- 双 active 任务隔离、双仓库门禁放行与未授权仓库拒绝测试结果。
- 阶段、授权、验证、CI 预算和证据敏感内容测试结果。
- 接管与 Tests Passed 状态意图、精确 transition 门禁、缺字段跳过、写后回读，以及 PR Ready 三类事实核对结果。
- 分阶段用例、单项单方式、用户处置、确认失效、并发恢复及评论回读的质量测试；真实测试平台和 Jira 联调验收与本地夹具验证分开记录。
- 双工作空间共享主工作树、worktree 准备/清理/重做、残留分支和动态 Agent 目录测试结果。
