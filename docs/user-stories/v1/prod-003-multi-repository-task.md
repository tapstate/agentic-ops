# PROD-003 推进并恢复多仓库研发任务

一个项目工位同一时间只接管一个 Jira 任务，每个任务可修改完整工程中的多个仓库；Agent 中断后恢复同一 run/op，汇总各仓 PR、CI 与验证证据。并发由多个独立工位承担。

### 验收标准

本节描述当前实现验收；待实现能力单列于“目标用户故事”。

- 用户只提供 Jira key 时，Agent 能从 Jira 设计/决定与 GitHub 分支/提交/PR/CI 核验既有成果，按本版 continuation-input 建立新 run。删除旧本地任务状态或跨多个 epoch 不要求迁移器；旧材料不足由 AI 协助补齐，缺失历史基线、外部结果未知或证据不足时不猜测。阶段评论包含实际工作分支、目标分支、完整历史基线和源码版本，不能把评论本身当已推送证明。

- 空闲工位可用 `station source-update` 刷新全部已准备仓库或指定仓库，只快进项目开发分支；活动任务、未完成操作、本地改动和分叉不允许刷新，批量结果逐仓报告。
- 阶段不可跳跃；准入按项目规则核对，缺少授权或可靠仓库基线会阻断受影响步骤。启用质量处置模式时，普通缺项先披露，推进检查点必须有用户处置记录，通用流程不要求所有测试全绿；TapData IT 的自动或手动闭环完成条件以[质量合同](../../usage/quality-checkpoints.md#测试编写缺口与-pr-总结)为准。
- 检查点包含多个检查项，每项绑定一个用例和一种验证方式；修复前后项分阶段到期，原始执行结果、用户选择和风险处置独立保存，具体操作见[质量检查与证据](../../usage/quality-checkpoints.md)。
- current-task.json 唯一绑定当前任务；新接管生成 Jira 任务号绑定的固定 8 位秒级 HEX run-id，恢复保持同一 run；operation 未结束阻止接新任务；活动授权、质量、CI 和证据精确绑定 run。
- 同工位不可并发任务；Workflow 状态变更显式绑定 issue/run，advance 另绑定预期阶段，旧请求失败关闭；不依赖通用工具 Hook。
- 一个授权绑定多个仓库，每仓独立校验 origin、分支、范围和验证方式。
- 新修改分支由工位首次固化的全局 Git `user.name` 与当前 run 生成；身份缺失只暂停代码变更步骤并给出补配说明，续办沿用已核验的历史分支。
- 每工位使用独立 source/<owner>/<repo> 和完整冻结工程基线；任务修改仓记录引用唯一基线。
- 同 run/op 恢复幂等；归档建立持久接续点，不冻结开发。两个清理范围先核实保全或放弃决定，资源未完成保留任务；最终材料回收未完成不释放执行占用。
- 当前 run 保存初始 Jira 快照和本地确认事实；版本不映射 Git 分支。接管水印尽力同步，外部失败或结果不明保留待办，不阻止本地推进；未知操作先回读。
- 缺陷接管成功后同步尝试一次 `In Progress`，Q4 验收完成后同步尝试一次 `Tests Passed`；已达目标直接记录，其它状态、必填字段不足或外部失败均记录并跳过，不阻断本地主流程，也不自动执行 `Pull Request Submitted`。
- PR 提审预检核对 Jira 关联 Test 接纳、当前完整 Head 的 Checks 及 Q1-Q4；有效具体 Checks 提审例外保留原始结果，未执行不冒充 PASS。预检通过后原生推进 GitHub Ready for review，全部目标 PR 身份、Head、OPEN 和非 Draft 回读确认后才报告 PR Ready；多仓部分成功与未知写入恢复使用[质量检查与证据](../../usage/quality-checkpoints.md#pr-ready-核对)。

### 保护行为

本节为现役保护要求，不因目标清理语义改变而提前撤除。

- 新增仓库或修改稳定绑定后旧授权失效。
- 其它工位源码、共享缓存、未知资源不能进入清理范围；未确认内容不删除。
- 清理前核实本地分支、未提交修改和唯一数据；缺少保全或放弃决定时拒绝删除。明确决定后归位并保留独立仓库，只有经核验无法恢复的具体仓库才删除重建，配置按 task/station 范围处理；外部对象和共享关系仍受保护。
- PR/CI 结果不改变授权指纹；合并和发布不被任务授权覆盖。
- Jira 状态及水印同步绑定当前 task/run 与精确目标；原生工具负责发送，Workflow 保存意图和回读，不保证工具调用次数。同步失败不能阻断无依赖的本地推进，也不能伪装成成功。
- 质量确认绑定对应计划、代码及证据；内容变化使受影响确认失效。旧 run、其它仓库的同号 PR、跳过或未知结果不能冒充当前用例通过；风险处置不能代替安全授权或 Jira Validator。
- 外部评论须先持久记录已确认草稿的写入意图；回执不明先核对，回读匹配后才能确认发送结果。记录损坏及并发旧 revision 保留现场并拒绝覆盖。
- 阶段同步评论只做阶段总结，实施方案写入 Issue Analysis，修复总结写入 Fix Details；字段和评论分别核验，不冒充同步完成。未知评论不阻止不同检查点回写，正文、目标与评论编号仍须匹配；显式字面文本表示只接纳已核验的服务端转换，真实差异拒绝。PR 后统一汇总同步警告。

### 普通授权期限验收

默认签发的授权在三天后仍可用于原范围检查点，不因时间失效；用户显式指定期限则到期拒绝。无固定期限的授权重新确认 Q2 后保持无固定期限；旧有限期限不自动移除，撤销及任务、方案、仓库绑定变化仍拒绝继续。损坏期限不能被解释为无期限。执行权另按下述会话交接场景验证。

### 同工位会话交接（当前实现）

首次有效会话的受管写入取得占用，缺少会话标识时写入给出补齐方式，但只读状态可用。同一会话隔三天继续操作不需重接管；另一会话不能直接写入；本地交接核实原执行者和在途操作，任务级决定另按 Jira 协调核验；并发争取只有一个成功，观察后原会话再次活动使旧交接材料失效。交接不改变原任务和 operation，旧会话返回不得继续受管写入。只读与失败操作不刷新已有活动时间，清除状态后不重建占用。

此场景仅验证当前本地检查点；下文 Jira 任务级协调另行验收，不能将这里的原子争取成功结论扩展到跨工位。它不证明能停止原生进程、认证会话或实现跨工位排他。手动平台和启动入口须按[执行接管](../../architecture/single-task-station.md#执行接管当前源码)传递本会话标识；真实操作与隔离并发测试分别保留证据。

### 当前清理与归档验收

源码复用须验证：集中展示 staged/unstaged、未跟踪及 ignored 唯一内容、未推送提交、本地 refs/stash；未处置时拒绝，已处置后归位旧基线并保留仓库及 .git 身份，下一任务不重新 clone。覆盖多仓、未冻结 no-checkout 状态、私有区归位失败、放回回执失败、新增内容保护、Git 锁/权限/漂移不触发删除、缺失对象的本地缓存或精确远端 SHA 恢复、远端明确拒绝后仅删除具体仓库及下一接管重建。v8 在途删除计划保留原语义；v9 新计划保留源码。运行区及配置仍按两个清理范围验收，真实耗时和流量没有实测时不报性能收益数字。

清理中的源码保全预检用真实隔离 Git 远端验证：同名远端引用完整 SHA、暂存/未暂存修改、未推送分支与 stash、未发布的 detached HEAD、忽略唯一文件与可再生产物、嵌套仓库及外部 worktree。未知远端不访问，远端不可用如实报告未核实；预检不改引用、索引、任务或接管活动时间，不删除文件。源码删除及恢复另按清理主流程验收，预检不是删除许可。

运行目录丢失后仍按工位标签发现并回收已核实容器/网络，无关对象和共享卷/镜像保留。驱动不可用或回读身份/结构异常保持未核验并引导 Agent 核实；无使用线索且未安装可选驱动的工位不要求安装 Docker。隔离夹具覆盖异常，真实本机网络验证发现、回收、无关网络保护和重复执行。

统一流程和场景以[单任务工位验收合同](../../architecture/single-task-station.md#11-可复用验收合同)为准。本故事另核验源码接管的完整基线、跨仓授权、交付、PR/CI 和质量证据；业务完成与本地退出分别验收。

必须覆盖任务中途放弃、归档后清理及新工位接续、多次归档、同工位多会话交接、空闲及未完成接管清理、资源目录丢失、私有目录删除中断、晚出现内容保护、最终材料回收恢复、配置保留与工位范围删除、再次接管。当前候选实现与真实验收结果分开报告，完整场景以工位合同为准。

运行代码候选由 affected staged 选择器正式验收，共享 Workflow、契约、Bootstrap 和未知影响回到完整四项。真实 TapData 工位退出另提供证据，不以模拟测试或归档成功冒充实际释放。

### 验收证据

- 双工位隔离、多仓基线与授权、阶段检查、PR/CI 和质量证据测试。
- Jira 同步意图与回读、缺项跳过、未知结果恢复测试。
- 配置清理、源码及 Git 保护、路径与资源身份、脚本异常接力和注销复用测试。
- 工位绑定校验、旧模式 epoch 保护，以及功能校验模式的原任务接续与局部修补；原版本退出及重建按适用范围另行验证。

工作项和本次执行结果记录于 Jira；旧归档冻结、强制会话覆盖、批量源码复位和清理计划修订合同由 Git 历史查阅，不作为本版验收标准。

### 持久归档接续验收

新增持久归档代码须验证：真实 Git 分支远端 Head 核实、未提交/未推送拒绝、明确放弃只记录不删除；Jira 原生回读对象/正文不匹配保持待核验；操作登记后正文保存前中断可沿原操作恢复，已保存正文不可替换；无变化正文复用、有变化保留旧点；本地副本 I/O 或格式异常不抹除已回读 Jira 点；新工位仅从 Jira 回读正文提取既有续办输入，旧工位、原 Product Root/档案和源码缓存完全不可用时，仍从远端恢复真实分支与历史基线且无旧授权；多次归档后按最新有效成果接续，清理恢复后的任务保留新工位配置。分支前进不静默替换旧保存点，先核实新成果或授权另建历史保全分支。自动化使用隔离本地 Git 远端和明确 Jira 回读夹具；真实服务另验，不把夹具通过当作实际写入成功。

## 目标用户故事

通用异常与跨功能闭环验收引用[开发原则](../../maintenance-guide.md#功能逻辑闭环验收)。本故事的接力场景须验证成功、未知结果和无安全路径三种结局：准确保留成果与缺口，反馈失败不扩大业务阻塞；现役实现缺口不能用模拟成功或 AI 手改状态补成通过。

以下为完整目标，已实现部分按上文当前验收执行，剩余部分待验证；不能以本节覆盖当前源码保护或授权期限。行为以[工位目标合同](../../architecture/single-task-station.md#任务生命周期目标合同)为准，分类只引用[数据规范](../../development-data-lifecycle.md)。不新增故事编号、阶段或验收入口，执行结果记录 Jira。

| 用户故事 | 场景与可观察验收结果 |
|---|---|
| 全新接管 | 工位无任务时读取 Jira，准备源码和必要输入，进入可执行状态；缺项引导补齐，接管中断沿原操作恢复，无悬空资源或重复运行身份 |
| 中途放弃并清理任务 | 展示未保全的修改、未推送提交、本地分支/stash及唯一数据，研发明确保留或放弃后归位源码并清理任务资源；配置保留，Jira 不伪称任务完成或保留已放弃进度；随后可正常接管 |
| 多次归档并跨工位接续 | 首次保存后继续开发，再次归档保留历史并指向新成果；无变化复用；部分失败不覆盖上次有效点，重试回读避免重复；归档后新增修改不能被清理漏检；新工位核实最新成果，补齐配置环境，旧执行者已停止 |
| 同一 Jira 任务跨会话、跨工位交接 | 按下述任务级协调场景验收；本地保护不再另设闲置业务规则，同一会话恢复核实未被接替后沿原 run 继续，新工位按当前流程接续成果 |
| 清理工位后重新使用 | 工位内用户配置、秘密副本、源码与运行数据清除，当前版本初始接线和登记有效；外部共享对象、持久成果和安装未误删；补齐配置后能接管，不要求先注销或重装 |

交叉验证：处理中升级保留有效成果，输入差异沿正常入口修补；无当前任务、配置损坏、运行目录丢失时仍可发现并处理确定归属的残留；创建/归档/清理中断可恢复且不扩大范围；独占卷与共享卷区分；未知外部写入先回读，唯一数据无备份不得误称可恢复；清理前真实停写，任务解绑不冒充资源清空；用户明确放弃无需强制归档。源码池热缓存重建验证时间、远端流量和依赖安装/编译成本，报告实际测量，不预设性能已满足。

### Jira 任务级接管协调验收（源码候选）

行为唯一引用[目标合同](../../architecture/single-task-station.md#jira-任务级接管协调与授权)。以下是可观察验收结果，不以现有本地会话测试通过代替；使用同一 Jira 任务及两个隔离工位，另以不同站点/任务 ID 验证隔离。

| 场景 | 验收结果 |
|---|---|
| 首次接管及正常继续 | 完整读取无占用后写入专用评论并回读；当前会话继续不重复询问；只读和普通 Jira 评论不刷新协调活动；无旧任务授权或 PASS 导入 |
| 活跃任务交接 | B 看到 A 的接管者、工位和服务端报告时间；阈值内无人工决定不开始冲突写入，有决定且核实旧写入风险后登记接替关系；观察后 A 再报活时重新核对旧决定 |
| 阈值边界与失联 | 刚好满 8 小时仅提示可能闲置；旧原生进程仍在写入或事实不明时不自动接管；同一执行者隔三天回来须先核实未被接替 |
| 同时争取与旧会话返回 | 两工位同时读到空闲或接替同一记录时，竞争记录可被发现并要求人工处置，不按最新时间静默胜出；旧会话回读发现被接替后停止冲突写入，更新旧评论不能夺回接管；不以测试声称全局原子互斥 |
| 记录与权限异常 | 多页历史中存在有效记录时不能误判空闲；缺记录、格式损坏、评论不可见、跨账号编辑权限不足及 Jira 不可用时披露缺口；只暂停依赖协调判断的动作，保留只读准备 |
| 写入超时及重试 | 服务端成功而回执丢失时沿原意图回读并复用，不重复新增；原会话丢失后经接续决定和停写核实仍能核验或取消明确未发送意图，不继承旧接管权；不同任务回读不得取消原意图，旧任务待办不阻塞其他任务；各工位独立编号不造成重复判定，本工位历史编号重用在发送前拒绝 |
| 归档、清理与交接交叉 | 归档后原接管仍有效；A 已被 B 接替后清理 A 无需夺回任务接管，只能结束 A 的记录；原归档冻结正文的回执、未开始删除的清理取消及原资源收尾回执可继续，不能借机新增任务动作；本地清理成功但 Jira 结束失败分别报告并保留恢复线索，后续可回读，不删除 B 的记录或共享历史 |
| 旧安装与未上报执行者 | 明确旧客户端不提供任务级协调，不能由“无评论”推定所有执行者均停写；目标测试不授权跨 epoch 采用旧状态 |

阈值边界和异常使用可控时钟、隔离并发及明确服务回读夹具；真实 Jira 另验证分页、不同账号可见性/自身评论编辑权限、服务端更新时间、人工交接和未知结果恢复。复用既有验收入口，不要求真实等待八小时，不新增后台服务或重复门禁。模拟、真实服务和发布支持范围分别报告，未实现项保持待验证。

### 旧任务升级后继续原 run

- 从旧版程序实际生成的任务和质量事件开始，在干净隔离安装中切换新版，任务状态、源码、配置与历史事件不被升级器改写。
- 正常读取继续同一 run；新增 Jira 协调缺失时写入口说明缺项，Agent 经原生回读和现有协调入口补齐后重试，历史事件保留且新增记录按当前合同校验，不继承 PASS。
- 跨 epoch 有工位且没有停写声明时拒绝切换；登记不可信、版本漂移、并发产品调用仍拒绝。旧目标保留原 epoch 回退保护。
- 旧在途操作含未知副作用或当前不支持的清理合同，先由 Agent 在原版本核实收尾；没有安全路径不得切换原共享安装，不把模拟任务验证宣称为任意历史操作迁移成功。

### 已确认的跨功能闭环验收

以下是目标验收，不以文档存在代表已实现。功能依赖描述与修补责任见维护规范；测试结果与未覆盖场景记录 Jira。

- 两个操作引用同一功能数据：公共结构修补一次，两个入口均可使用；操作特有缺项不阻塞另一操作；并发修改拒绝覆盖，失败不留下半转换状态。
- 旧版中途任务升级后，Agent 先整理依赖差异，再经研发确认、所属功能复查，保留事实及有效成果继续下一步骤；程序自身缺陷不靠 Agent 改控制状态绕过。
- 新工位依据最新有效 Jira 决定、远端 Git 和必要材料恢复已完成事项，不机械导入旧阶段，也不无理由重做已确认方案或有效验证。
- 清理的本地成果处置与 Jira 成果有效性分别报告；删除本地副本不撤销远端成果，明确放弃原成果才补充其不再适用的决定，历史保留。
- 环境配置、构建、部署和原生工具接力分别经所属接口复查；配置静态通过不等于应用启动，资源回收不要求部署健康。
- 产品异常反馈先去重，同问题补新增证据评论；反馈服务失败不扩大业务阻塞，外部结果未知先回读。
- 完整组合覆盖处理中升级、差异修补、继续处理、多次归档、旧工位丢失后新工位接续、任务清理、工位清理和再次接管；分别报告自动化、真实服务与实际安装结果。

### IT 手动验证与兼容跟进验收

按[质量合同](../../usage/quality-checkpoints.md#测试编写缺口与-pr-总结)验证 L1/L2 自动路径、框架不支持和当前 L3 的手动路径；Q2 只检查计划映射，Q4 对缺执行、错误负责人、缺 Jira 关联、重复回读集中返回且不放行。核对部分补齐后的剩余缺项、代码/用例/方案变化失效、旧规则历史重放、外部写入未知后回读及跨仓复用同一任务；PR 必须区分自动化缺口与手动通过。测试夹具不替代真实 Jira 创建、去重、关联和分派的端到端证据，实际材料记录在 Jira。
