# PROD-003 推进并恢复多仓库研发任务

一个项目工位同一时间只接管一个 Jira 任务，每个任务可修改完整工程中的多个仓库；Agent 中断后恢复同一 run/op，汇总各仓 PR、CI 与验证证据。并发由多个独立工位承担。

### 验收标准

- 用户只提供 Jira key 时，Agent 能从 Jira 设计/决定与 GitHub 分支/提交/PR/CI 核验既有成果，按本版 continuation-input 建立新 run。删除旧本地任务状态或跨多个 epoch 不要求迁移器；旧材料不足由 AI 协助补齐，缺失历史基线、外部结果未知或证据不足时不猜测。阶段评论包含实际工作分支、目标分支、完整历史基线和源码版本，不能把评论本身当已推送证明。

- 清理按六个固定阶段自动推进，阶段出口核验实际成果；异常列全具体对象，Agent 接管后沿原操作恢复。正常源码链接不跟随目标，批量复位回到项目开发分支并回收已保全的受管临时基线，任务成果分支保留，明确分支处置在释放前完成；已通过阶段不重删新增内容。兼容边界见[阶段式清理](../../architecture/single-task-station.md#阶段式清理)。

- 空闲工位可用 `station source-update` 刷新全部已准备仓库或指定仓库，只快进项目开发分支；活动任务、未完成操作、本地改动和分叉不允许刷新，批量结果逐仓报告。
- 阶段不可跳跃；准入按项目规则核对，缺少授权或可靠仓库基线会阻断受影响步骤。启用质量处置模式时，普通缺项先披露，推进检查点必须有用户处置记录，不要求所有测试全绿。
- 检查点包含多个检查项，每项绑定一个用例和一种验证方式；修复前后项分阶段到期，原始执行结果、用户选择和风险处置独立保存，具体操作见[质量检查与证据](../../usage/quality-checkpoints.md)。
- current-task.json 唯一绑定当前任务；新接管生成 Jira 任务号绑定的固定 8 位秒级 HEX run-id，恢复保持同一 run；operation 未结束阻止接新任务；活动授权、质量、CI 和证据精确绑定 run。
- 同工位不可并发任务；Workflow 状态变更显式绑定 issue/run，advance 另绑定预期阶段，旧请求失败关闭；不依赖通用工具 Hook。
- 一个授权绑定多个仓库，每仓独立校验 origin、分支、范围和验证方式。
- 新修改分支由工位首次固化的全局 Git `user.name` 与当前 run 生成；身份缺失只暂停代码变更步骤并给出补配说明，续办沿用已核验的历史分支。
- 每工位使用独立 source/<owner>/<repo> 和完整冻结工程基线；任务修改仓记录引用唯一基线。
- 同 run/op 恢复幂等；归档未完成任务后停止开发且仍占用，精确 clean 成功才释放；完成任务由研发 release。
- 清理按明确成果标准验收，内置脚本和 Agent 原生工具使用同一标准；脚本异常可在原授权范围接力，不以命令退出码或指定中间步骤作为完成依据。实际残留、保全不足或事实不明不能解绑，具体合同见[成果导向清理](../../architecture/single-task-station.md#成果导向清理计划版本-6)。
- 当前 run 保存初始 Jira 快照和本地确认事实；版本不映射 Git 分支。接管水印尽力同步，外部失败或结果不明保留待办，不阻止本地推进；未知操作先回读。
- 缺陷接管成功后同步尝试一次 `In Progress`，Q4 验收完成后同步尝试一次 `Tests Passed`；已达目标直接记录，其它状态、必填字段不足或外部失败均记录并跳过，不阻断本地主流程，也不自动执行 `Pull Request Submitted`。
- PR 提审预检核对 Jira 关联 Test 接纳、当前完整 Head 的 Checks 及 Q1-Q4；有效具体 Checks 提审例外保留原始结果，未执行不冒充 PASS。预检通过后原生推进 GitHub Ready for review，全部目标 PR 身份、Head、OPEN 和非 Draft 回读确认后才报告 PR Ready；多仓部分成功与未知写入恢复使用[质量检查与证据](../../usage/quality-checkpoints.md#pr-ready-核对)。

- 新清理计划不依赖创建时的设备号或 inode；清理确认绑定本次实际身份，执行中漂移拒绝。同操作补充确认不得覆盖历史完成回执或重删再生内容，详见[目录归属与操作身份](../../architecture/single-task-station.md#目录归属与操作身份)。

### 保护行为

- 新增仓库或修改稳定绑定后旧授权失效。
- 其它工位源码、共享缓存、未知资源不能进入清理范围；未确认内容不删除。
- 本地任务分支与独立仓库保留；残留分支不静默复用，源码中的暂存、未暂存、未跟踪和 ignored 内容按确认快照保全或明确处置，不按构建目录名称删除。运行目录按当前任务归属回收，未知范围不删除。
- PR/CI 结果不改变授权指纹；合并和发布不被任务授权覆盖。
- Jira 状态及水印同步绑定当前 task/run 与精确目标；原生工具负责发送，Workflow 保存意图和回读，不保证工具调用次数。同步失败不能阻断无依赖的本地推进，也不能伪装成成功。
- 质量确认绑定对应计划、代码及证据；内容变化使受影响确认失效。旧 run、其它仓库的同号 PR、跳过或未知结果不能冒充当前用例通过；风险处置不能代替安全授权或 Jira Validator。
- 外部评论须先持久记录已确认草稿的写入意图；回执不明先核对，回读匹配后才能确认发送结果。记录损坏及并发旧 revision 保留现场并拒绝覆盖。
- 评论只做阶段总结，实施方案写入 Issue Analysis，修复总结写入 Fix Details；字段和评论分别核验，不冒充同步完成。未知评论不阻止不同检查点回写，正文、目标与评论编号仍须匹配；显式字面文本表示只接纳已核验的服务端转换，真实差异拒绝。PR 后统一汇总同步警告。

### 统一退出优化目标验收

以下场景验证[统一退出优化目标](../../architecture/single-task-station.md#归档清理与升级的统一退出优化目标)，与已实现的 epoch 28 两类档案分别提供证据；原 epoch 修复、新默认合同和真实工位退出分别提供证据。

| 场景 | 必须观察到的结果 |
|---|---|
| 当时制品已经移除 | 历史 checkpoint/auto_checkpoint 重放同一模型且零文件/Git/网络调用；当前报告和新验证仍拒绝缺失或变化制品，损坏事件仍拒绝 |
| 清理检查已有外部意图 | 零 quality.report/context 调用；制品缺失不阻塞已核验写入；当前及旧 run 未知写入仍阻塞，关闭当前质量模式不漏检，损坏记录不得容错成空清单 |
| completed release 在两个仓库间中断 | 保留 completed、原档案、原请求及已完成回执，按原 operation 完成其它仓库和资源，不恢复 Jar、不重跑测试、不重删再生对象 |
| 100,000 个生成物 | 聚合用途、数量/字节和精确处置，一份决定覆盖当前范围；默认预检、成功、失败、修订输出均不超过 64 KiB，完整清单与 proof 可回读 |
| 大控制文件及小会话正文 | source-disposition、质量和冻结清单不被当作会话套用 16 MiB 输入限额；对应控制读取及结构仍严格验证，正文投影后才核算容量 |
| 容量、敏感或不支持对象 | 正式执行前列明适用配额和实际编码大小，完整范围不冒充可归档；未知或新增成果继续保全，无清理报告再次进入输入的自引用 |
| 声明两个会话来源只提交一个 | 不能 complete；摘要、截断、缺页/块或未知边界显示缺口，完整要求不被静默降级 |
| 明确接受当前覆盖或放弃会话 | 绑定声明范围和正文的接受摘要才允许最小状态/回执退出，一次处置决定；范围、截止点、正文或缺口变化使旧接受失效 |
| 确认之后产生新消息 | 正文截止点在确认前固定，确认来源及进度由状态/回执补全；不自动重算正文并递归要求新确认 |
| completed、pending 未冻结、冻结草稿和正式档案 | 分别验证退出输入分配、原 op/revision 绑定、持锁修订及正式正文禁止补写；分配文件不冒充已经纳入档案 |
| 会话录入/修订中断 | 部分写入保持待恢复并可用相同外部清单回读，未知目标不覆盖；错 run/op、第三方内容漂移和旧摘要重放拒绝 |
| 已合入 PR 与最终验收 | 同一最终 Head、实际 Checks 与有效具体例外在 PR Ready 和完成判定一致；旧 Head/不同 Checks 或未决验收继续拒绝业务 completed，明确已交付及已验收事实仍保留，安全 clean 可以释放工位 |
| 未完成 run 及已交付功能 | 外部交付、本地验收和工位退出分别报告；允许如实 clean，不借其它分支验收改成 completed，不要求过期开发授权重签 |
| 原生构建 clean 失败或遗漏装配目录 | 同一已确认范围内接力，保留源码/配置/未知对象；构建清理成功不等于工位已释放 |
| 归档完成而清理中断后请求注销 | 分别显示归档、原操作已完成/剩余对象、占用及注销结果；仅当前状态证明释放后执行 purge，不直接删除状态或恢复 Jar |
| 原范围决定及平台审批 | 原真实决定未变化时跨会话复用；平台拒绝的动作无执行结果，补足缺少的具体授权后仍沿原 operation，不绕过或重删 |
| 缺陷处理结束 | 说明根因、前后行为、候选/安装版本和实测结果；设计就绪、候选通过、安装应用及真实退出分别报告，未完成内容明确列出 |
| 原版修复与新版切换 | 兼容补丁先退出/purge，再串联 PROD-001 的旧客户端、共享安装、产品切换和新 run 接续；不跨 epoch 恢复旧 operation |

运行代码候选由 affected staged 选择器正式验收，共享 Workflow、契约、Bootstrap 和未知影响回到完整四项。性能在相同夹具比较盘点、Git、读取及写入次数和输出大小；真实应用及原现场恢复另提供证据，不以模拟耗时承诺所有机器性能。

### 验收证据

- epoch28 验证任务档案只含会话与状态正文，构建/依赖/日志字节不入档，原文覆盖缺口不得标完整；未提交成果独立 export/discard。归档截止点与终态 receipts 分开，批量登记空窗恢复不获得额外删除权；旧 epoch27 由原版本退出与 purge，不在线迁移。

- 双工位任务隔离、双仓库门禁放行与未授权仓库拒绝测试结果。
- 阶段、授权、验证、CI 预算和证据敏感内容测试结果。
- 接管水印与状态意图、缺字段跳过、写后回读、外部失败不阻断本地推进，以及 PR Ready 三类事实核对结果。
- 分阶段用例、单项单方式、用户处置、确认失效、并发恢复及评论回读的质量测试；真实测试平台和 Jira 联调验收与本地夹具验证分开记录。
- 双工位隔离、完整基线、四操作恢复、目录重置、会话覆盖及脱敏、独立源码导出可重建、档案不变、refs保留和顺序复用测试。
- 同名源码目录保护、无构建配方清理、未登记 ignored 成果保全、脚本部分失败或完全不执行时的 Agent 接力、成功退出但残留拒绝、解绑中断后证据复核及跨 epoch 拒绝测试。

- epoch 26 清理计划冻结规则、结构合同与扫描边界；仓库和规则批次分别记录完成回执，部分失败恢复不得重删已完成对象的新内容。确认后身份变化及新增扫描目录拒绝；epoch 25 及以前须由原版本结束任务、归档清理及 purge，历史档案不改写。
