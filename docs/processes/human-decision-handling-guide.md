# 人工决策项处理规范指引

## 1. 目的与适用范围

本指引用于把 AgenticOps 流程中的人工确认、审批和风险处置整理为可判断、可授权、可执行、可回读的决策项。它适用于 `maintainer` 源头维护工作面和 `developer` 业务项目工作面；不改变各项目既有的 Jira、Git、GitHub、CI、QA、安全或发布流程。

人工决策的目的不是把 Runtime 可以确定的输入、摘要、路径或内部标识转交给人，也不是为每个原子步骤重复取得许可。它只处理以下情形：业务语义、授权范围、外部事实或风险不能由已确认合同安全决定，且继续执行会产生实质影响。

Jira 是任务、进度、评论和任务证据的事实源；Git 是代码、提交与分支的事实源；GitHub / CI 是 PR、检查和合入事实源。本地运行状态和决策审计只用于恢复与追溯，不能替代上述外部事实。

## 2. 基本原则

1. **先核实，后决策。** 决策包必须引用已回读的事实；不以聊天记忆、旧摘要、单个 `ok=true` 或未验证的本地日志作为依据。
2. **一项决策只回答一个可执行问题。** 同一业务语义下可把彼此依赖的范围、验证和授权边界合并展示；无关问题必须拆开，避免“同意全部”。
3. **以最小充分授权推进。** 授权只覆盖明确的任务、运行、仓库、分支、动作、验证和有效期；未列出的动作仍未获授权。
4. **选项可比较，推荐可追责。** 至少说明推荐方案、备选方案及其影响；没有安全可行选项时，明确建议停止或转人工执行。
5. **决策绑定当前事实。** 任何关键绑定事实变化后，原决策失效，必须重新展示受影响内容；不得沿用旧批准。
6. **外部写入必须闭环。** 对 Jira、Git、GitHub、CI 或其他外部系统的写入，按对应 Runtime 的 `plan → apply → readback` 或等价受控流程执行；结果不明确时先回读，不盲目重试。
7. **人可见、中文、可审计。** 面向指导员、审查人或 Jira 的决策内容使用中文；不得要求人确认内部 `impact_id`、digest、临时路径或其他不具业务意义的标识。

## 3. 何时形成决策项

下表是固定类型。Runtime 已能安全确定且不改变业务语义的事项，应自动处理并记录，不得升级为人工决策。

| 决策类型 | 触发条件 | 决策人需要决定什么 | 决策结果 |
| --- | --- | --- | --- |
| 信息补充 | 必要业务事实、验收条件、所有权或输入缺失 | 补充、澄清或确认缺失事实 | 返回分析/方案阶段；不能凭猜测继续 |
| 设计审查 | 方案、范围、仓库、分支和验证方式已完整 | 是否认可当前设计并授予工作项级连续执行授权 | 在授权范围内连续实现、验证、提交、推送与必要回写，停在后续独立门禁 |
| 代码审查 | 当前本地 commit 或 PR Head 已形成且固定验收完成 | 是否认可当前代码事实并允许下一受保护动作 | 推送、PR 审查结论或请求修改；确认只绑定当前 commit / PR Head |
| 风险决策 | 所有权、范围、仓库、分支、验证、外部事实变化；权限冲突；连续失败；外部写入结果不明确 | 选择继续、收缩范围、等待、转人工或放弃候选 | 建立新的边界或停止；不得沿用旧连续授权 |
| 连续性决策 | 仅因 AgenticOps 缺陷、能力缺口、内部状态或配套工具故障阻断业务开发，且安全自检、有限重试和只读对账均不能恢复 | 等待 AO 修复、按项目原生流程有限继续，或人工接手 | 形成受限降级授权与审计；不得伪造 AO 成功 |
| 受保护动作确认 | 合并、正常发布、Tag、直接修改受保护分支、强推、历史改写，或项目另行规定的高风险动作 | 是否授权这一次精确受保护动作 | 只执行该动作及其验证；不扩展为普通持续授权 |
| 范围变更 | 已确认方案的目标、非目标、交付仓库、关键接口、数据处理方式或验证基线变化 | 是否接受新的业务语义和实施边界 | 旧设计/风险/代码审查授权失效，重新分析并形成新的决策包 |

`maintainer/scripts/hotfix.sh <KEY>` 是项目规则定义的唯一脚本化例外：显式命令调用本身构成该次受限 Hotfix 授权。它不应被泛化为普通直推、Jira 写入、强推、发布或其他受保护动作的自动放行。

## 4. 决策包的最低内容

每个决策项必须一次性给出足以判断的信息；信息不足时先补充事实，不以模糊问题要求人承担分析工作。决策包至少包含：

| 字段 | 要求 |
| --- | --- |
| 决策标题与类型 | 使用中文标题，标明本节第 3 条的类型。 |
| 待决问题 | 用一句可回答的话说明“需要决定什么”，避免“请确认”这类空泛表述。 |
| 绑定对象 | Jira key、运行 ID、工作面、仓库、当前分支、目标分支，以及当前 commit 或 PR Head（适用时）。 |
| 已确认事实与证据 | 列出事实、来源、回读时间或不可变引用；区分已确认事实、假设和未知项。 |
| 方案与推荐 | 至少给出推荐方案与可行备选；说明推荐理由。无安全方案时明确写“建议停止/转人工”。 |
| 授权边界 | 允许与禁止的动作、文件/模块范围、仓库/分支、外部写入、验证方式、有效期和失效条件。 |
| 影响与风险 | 说明对任务、代码、数据、审计、交付节奏和后续门禁的影响，以及剩余风险。 |
| 验证与恢复 | 成功判据、回读动作、失败后的停止线、候选保存位置或恢复入口（适用时）。 |
| 记录位置 | 需要回写的 Jira Comment / Description、Runtime 决策审计和关联 PR 或提交。 |

对代码审查，必须额外列出“确认事项、变更点、验证结果和风险”；对连续性决策，必须额外列出“故障证据、已确认业务事实、损失的自动化审计能力、精确降级授权与时效”；对外部写入，必须额外列出计划摘要与 readback 判据。

## 5. 标准处理流程

```text
识别真实人工门禁
-> 收集并回读事实
-> 形成最小决策包
-> 人工明确选择
-> 记录决策与授权边界
-> 受控执行
-> 外部结果回读
-> 汇报结果、剩余风险与下一门禁
```

### 5.1 识别与准备

1. 先消费 Runtime 返回的 `agentic_next_action`，只在真实人工节点、结构化阻断或独立受保护动作处暂停。
2. 判断问题是否只是内部载体错误、可自助恢复项或可安全重试项。若是，先按 Runtime 指引处理；不得把内部路径、digest 或规范化错误包装成用户决策。
3. 对需要人工选择的事项，读取 Jira、Git、GitHub / CI 和 Runtime 的当前事实，并标出证据时点。外部状态或写入结果不明确时，先回读。
4. 检查当前工作项级连续执行授权是否仍覆盖该动作。范围、风险、绑定或关键事实变化时立即失效，不得以“此前已同意”继续推进。

### 5.2 展示与确认

1. 按第 4 节展示完整决策包，明确推荐项而不替人作决定。
2. 人工答复必须能映射到具体选项或明确授权边界。例如：“同意方案 A；仅限 `repo-x` 的 `feature/AO-123`；按列出的验证执行；有效至本次 PR 审查。”
3. “看一下”“继续”“同意”仅在当前对话中唯一、完整且无歧义地对应一个决策包时才可接受；否则必须澄清，不得扩张解释。
4. 人工拒绝、选择备选、缩小范围或补充条件时，重新计算受影响的范围、风险和验证；必要时重新分析、分级和展示。

### 5.3 执行、回读与归档

1. 将决策摘要、确认人、授权边界、绑定事实和失效条件写入 Runtime 受管决策审计；涉及 Jira 的可见决策轨迹按项目规则用中文回写并读回。
2. 使用对应工作面的 Runtime 执行外部写入。Jira 写入必须保留计划、授权引用、apply 结果和 readback；禁止直接调用 Connector、REST API 或 Shell 网络请求绕过 Runtime。
3. 执行后回读外部事实。成功才报告完成；若结果不明确，保留现场并先回读，不重复具有副作用的动作。
4. 向人工汇报实际执行结果、证据链接或不可变引用、未执行项、残留风险，以及下一次需要人工判断的门禁。原子操作成功不等于整个任务完成。

## 6. 授权有效性与失效

| 情形 | 原决策是否可继续使用 | 处理方式 |
| --- | --- | --- |
| 仅内部摘要、路径或参数规范化变化，业务语义和所有绑定事实未变 | 可以 | Runtime 自动修正并保留审计，不重新打扰人工。 |
| Jira / Profile 快照、源码 HEAD、PR Head、范围、风险、方案、仓库、分支或验证方式变化 | 不可以 | 重新读取事实，重新分析并展示受影响决策项。 |
| 审查人提出修改，或固定验收失败 | 不可以 | 修复后重新验证，形成新的 commit / PR Head 再审查。 |
| 外部写入结果不明确、连续失败、权限或所有权冲突 | 不可以 | 先回读和诊断；仍无法消除时进入风险决策。 |
| 到达确认的代码审查、合并、发布、Tag、强推或历史改写门禁 | 不可以自动跨越 | 单独形成该受保护动作的决策项。 |
| 决策包明确的时效届满 | 不可以 | 重新确认当前事实和授权。 |

## 7. 工作面与记录边界

- `maintainer` 只处理 AO 项目 Jira 任务，使用 `ao-maint` 和 `maintainer/` 命名空间。AO Jira 写入仍执行 `plan → apply → readback`，并记录受管决策审计。
- `developer` 只在业务项目工作空间使用 `ao-work` 与 developer 资产；不得加载 maintainer 授权、状态或规则来替代业务项目决策。
- 设计、风险和代码审查的业务可见轨迹写入 Jira Comment；稳定需求、范围、非目标、实施计划和验收标准按流程写入 Jira Description。Worklog 只记录真实投入时间，不承载决策或授权。
- 本地状态、`decisions.ndjson`、运行日志、候选分支或补丁仅保存恢复与审计材料，不能替代 Jira、Git、GitHub 或 CI 的当前事实。
- 不记录 token、密码、私钥、敏感原始响应或不必要的本机绝对路径。涉及敏感证据时只保留脱敏摘要和可控访问引用。

## 8. 禁止事项

- 不以“Runtime 成功”“计划已生成”或内部 ID 代替人工决策或外部 readback。
- 不把每个命令、每个仓库或每个内部校验拆成重复确认，消耗人工注意力。
- 不用旧 commit、旧 PR 审批、旧授权、非空字符串或聊天印象覆盖已变化的事实。
- 不在授权范围外增加仓库、分支、文件、外部写入、数据影响或受保护动作。
- 不把 AgenticOps 自身故障伪装为业务阻断，也不在未经明确授权时静默降级到项目原生流程。
- 不因阻断而丢弃已经验证的候选；应先按工作面规则转存候选、证据和恢复入口，再恢复干净工作树。
- 不将“人工决定”当作绕过权限、事实源、审查、测试、发布或安全控制的理由。

## 9. 人工决策项模板

以下模板用于对话、Jira Comment 或受管表单；方括号内容必须替换，未知项明确标为“未获取”。

```markdown
## 人工决策：<中文标题>

- 决策类型：<设计审查 / 代码审查 / 风险决策 / 连续性决策 / 受保护动作确认>
- 待决问题：<一句可回答的问题>
- 绑定对象：<Jira key；run ID；工作面；仓库/分支；commit 或 PR Head>

### 已确认事实与证据

- <事实>：<来源、回读时间或不可变引用>
- 假设/未知：<明确列出，或“无”>

### 选项与推荐

1. **方案 A（推荐）**：<动作、理由、影响>
2. 方案 B：<动作、影响>
3. <无安全方案时：停止或转人工执行>

### 拟授权边界

- 允许：<任务、仓库、分支、文件范围、动作、外部写入、验证>
- 禁止：<不在本次授权内的动作>
- 有效期与失效条件：<时点；哪些事实变化即失效>

### 风险、验证与恢复

- 残留风险：<风险及承担方式>
- 验证与回读：<命令/检查、外部 readback、成功判据>
- 失败停止线与恢复入口：<何时停止；候选/审计位置>

请明确选择方案，并确认上述授权边界；若选择其他方案，请说明变更的范围、动作或条件。
```

## 10. 质量检查清单

在提出或执行人工决策项前，执行者应确认：

- [ ] 这是一个真实人工门禁，而非 Runtime 可确定的内部细节。
- [ ] 待决问题、推荐方案和至少一个可行替代或停止路径已清楚说明。
- [ ] 已确认事实、假设和未知项已分开，外部事实已回读。
- [ ] 授权边界覆盖任务、仓库、分支、动作、验证、时效和禁止项。
- [ ] 代码审查已列出确认事项、变更点、验证结果和风险。
- [ ] 连续性决策已列出 AO 故障证据、审计损失、降级边界和剩余风险。
- [ ] 需要外部写入时已定义 plan、apply、readback 与结果不明确时的停止线。
- [ ] 已明确决策记录位置，且不含敏感信息。
- [ ] 执行结果将回读并向人工说明下一门禁或终态。
