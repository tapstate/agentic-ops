# AgenticOps 目标定位

## 1. 一句话定位

AgenticOps 是把公司员工执行标准沉淀成 AI 可执行标准流程的 AI 执行控制体系。

AgenticOps 先以研发 Jira 任务为主要落地场景：帮助研发工程师操作 AIAgent 从 Jira 接管任务到完成任务。它让不同任务按各自需要的流程推进，让执行过程留下可恢复、可复盘的记录，并把关键状态、关键信息、表单数据和证据回写到 Jira、拉取请求或项目 AI 工作空间，用于分析和优化。

## 2. AgenticOps 是什么

AgenticOps 是：

- AI 员工在研发流程中工作的执行体系。
- 公司员工执行标准的 AI 可执行载体。
- 面向研发工程师的 AI 员工操作入口。
- 面向 AIAgent 的工作手册、操作契约和工具边界。
- 面向团队流程的 工作流配置。
- 面向不同任务类型的受控流程入口。
- 面向不同专业角色的节点审查机制。
- 面向任务生命周期的标准表单和状态推进机制。
- 面向成熟交互逻辑的原子化操作入口。
- 面向标准异常的自助修复、阻断和转人工机制。
- 面向任务执行的证据和反馈闭环。

## 3. AgenticOps 不是什么

AgenticOps 不是：

- 新 Jira。
- 新 DevOps 平台。
- 全自动研发机器人。
- 单纯 prompt 集合。
- 脱离研发工程师的自动任务分派系统。
- 脱离 Jira / Git / GitHub 的新事实源。
- 只靠培训员工记住流程的知识库。

## 4. 主要用户

首要用户是研发工程师。

研发工程师使用 AgenticOps：

- 安装全局工具和手册。
- 初始化项目 AI 工作空间。
- 初始化 AIAgent 能力。
- 拉取自己名下 Jira 待办。
- 授权 AI 员工接管一个 issue。
- 确认版本化设计或修复计划，并授予工作项级连续执行授权。
- 在拉取请求审查节点统一审查本地变更、提交、验证和证据。
- 查看任务审计记录和按需反馈分析报告。

## 5. 项目价值

AgenticOps 的价值：

- 把公司员工执行标准沉淀为 AI 可执行、可审计、可回滚的规范资产。
- 让 AI 员工从临时聊天助手变成流程内可管理执行状态。
- 保留研发工程师、代码审查人、QA、运维、安全或其他专业角色在对应节点的审查责任边界。
- 让 AI 执行过程有可追踪证据链。
- 让每个流程节点通过标准表单表达已完成事项、审查结论、失败原因和下一步动作。
- 让不同任务按匹配的流程推进，而不是把所有任务压成同一条固定流程。
- 让关键状态和信息及时回写，避免任务进展只停留在聊天上下文里。
- 让失败、阻塞和人工确认点可被反馈分析。
- 让重试和重做有明确依据：基于表单数据判断从哪个阶段恢复、需要谁补充信息、哪些节点必须重新审查。
- 让标准流程出问题时，AIAgent 能优先自助处理；不能安全处理时，明确阻断、记录原因并转人工。
- 让成熟固化的交互逻辑沉淀为稳定、可复用、可审计的原子化操作；脚本入口只做受控编排或调用。
- 让框架保持稳定和高容错，只定义大的流程环节、门禁、状态和演进边界。
- 让研发员工经过简单培训即可使用标准流程，而不需要记住所有细节。
- 用项目规则、AI 工作规则和 操作契约减少幻觉。
- 用 Go CLI 运行时 让关键动作可检查、可拒绝、可审计，并便于向全公司研发稳定分发。

AgenticOps 中的关键标准资产包括：

- AI 员工手册：定义 AIAgent 如何接任务、何时停止、如何回写证据。
- AgenticCLI：承载成熟经验沉淀后的原子操作，提供稳定、结构化、可审计的执行入口。
- 操作契约：定义每类操作的输入、输出、失败码和副作用。
- 工作流配置：定义不同项目和系统流程如何映射到标准操作。
- Policy / Gate：定义哪些动作必须人工确认，哪些动作禁止自动执行。
- Runbook：定义标准流程出问题时如何排查、修复、阻断或转人工。
- 模板：定义 Jira 评论、拉取请求证据、阻塞说明、补卡说明等标准输出。

## 6. 标准执行模型

AgenticOps 的核心不是让 AIAgent 自由发挥，而是让 AIAgent 按公司已经认可的员工执行标准工作。

一个标准流程至少包含四类信息：

- 标准动作：当前角色或 AIAgent 在该节点必须完成什么。
- 标准表单：完成动作后必须输出哪些结构化数据，代表做过哪些事项。
- 专业审查：由研发工程师、代码审查人、QA、运维、安全或其他专业角色在对应节点判断结果是否合格。
- 推进规则：根据表单数据、审查结论、失败码和人工门禁决定下一步、重试、重做或停止。

AIAgent 每完成一个环节，都必须把该环节的标准表单数据写回任务事实源或项目 AI 工作空间。后续操作不应只依赖聊天上下文判断进度，而应读取这些表单数据和事件记录来决定 `task_type`、`current_stage`、`agentic_next_action`。

## 7. 框架、脚本和经验沉淀

AgenticOps 的框架和脚本职责必须分开。

- 框架负责定义大的流程环节、阶段状态、门禁、错误模型、重试重做边界和演进机制。
- `Operation` 负责承载已经成熟固化的交互逻辑，提供稳定、原子化、可验证的操作入口；脚本入口只做受控编排或调用，不承载业务判断。
- AIAgent 负责在具体环节内完成任务、处理上下文差异、按标准回写表单和证据。
- 周期性复盘负责把 AIAgent 执行经验、失败模式、人工退回和重复问题转化为工作流配置、策略、运行手册、模板或操作的改进建议。

脚本不应承载流程判断，也不应把高层框架写死。框架也不应过度细化到每个任务的临场操作细节；这些细节先由 AIAgent 执行并沉淀经验，经过复盘和审查后再固化为标准资产。

## 8. 目标主链路

AgenticOps 应能解释并演示这条链路：

```text
安装 AgenticOps
-> 初始化项目 AI 工作空间
-> 初始化 AIAgent 能力
-> 拉取 Jira 待办
-> 接管新任务
-> 形成版本化设计或修复计划
-> 人工确认计划并授予工作项级连续执行授权
-> 实现、验证、提交、推送、回写证据并创建拉取请求
-> 人工审查拉取请求
-> 提交任务完成审计
-> 生成改进建议
```
