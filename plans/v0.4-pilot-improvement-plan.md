# AgenticOps v0.4 真实试运行改进实施计划

> **AIAgent 执行要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务实施本计划。步骤使用勾选框（`- [ ]`）跟踪。

**目标：** 修复 v0.3 AO-2 真实试运行证实的七个问题，使安装、真实时间、Jira 原子接管、运行上下文、中文证据、GitHub PR 事实和人工恢复反馈形成可回读、可审计、可测试的 v0.4 完整链路。

**架构：** 实施分为运行时基础、Jira 生命周期与证据、GitHub 与反馈恢复三条轨道。每条轨道先建立独立 RED 用例，再完成最小实现和聚焦提交；最后统一更新安装资源、执行四个 E2E 和完整构建，并在新的真实 AO 工作项中按独立人工门禁验收。

**技术栈：** Go 1.x、Bash、Jira Cloud REST API v3、GitHub REST API、GitHub CLI、Markdown、YAML、JSON、Git。

## 全局约束

- 实施前必须取得新的真实 AO Jira key，并设置 `V04_JIRA_KEY`；所有提交使用该 key，不复用 AO-2。
- 从最新 `origin/develop` 创建 `harsen/$V04_JIRA_KEY/develop`，不得直接提交或推送 `develop`、`main`。
- 三条轨道分别提交；每个提交只包含一个可独立测试和审阅的逻辑变更。
- 测试先于实现；每个 RED 步骤必须确认失败原因正是目标能力缺失，不能接受编译环境或 fixture 错误代替业务失败。
- Jira、Git、GitHub 和 CI 保持权威事实源；本地事件只保存连续性、门禁和恢复审计。
- 不自动合并 PR、完成 Jira、批准人工门禁或绕过现有策略。
- 真实 Jira 写入、评论、转换、Git commit、push、PR 创建、合并和任务完成分别请求确认。
- 所有 Jira 人可见内容使用中文；字段名、状态名、命令、错误码和代码标识可保留原文并用中文解释。
- 自动化测试只使用 fake Jira、GitHub fixture 和临时工作空间，不执行真实外部写入。
- 不修改 v0.3 Tag、版本号规则、发布流程和分支规则。
- 不提交 token、cookie、private key、凭证、原始敏感响应、本机绝对路径或临时安装目录。
- 运行代码完成后必须执行 `go test ./...`、资源测试、构建测试、安装测试和四个固定 E2E 流程。

在 `scripts/install.sh` 增加：

```bash
default_install_dir="$HOME/.agentic-ops"
path_profile_action=""

is_default_install() {
  [ "$(cd "$(dirname "$INSTALL_DIR")" && pwd -P)/$(basename "$INSTALL_DIR")" = \
    "$(cd "$(dirname "$default_install_dir")" && pwd -P)/$(basename "$default_install_dir")" ]
}

configure_path_profile() {
  local profile="$1"
  local line="$2"
  if ! is_default_install && [ "${AGENTIC_OPS_CONFIGURE_PATH:-0}" != "1" ]; then
    path_profile_action="skipped_custom_home"
    return 0
  fi
  if grep -Fqx "$line" "$profile" 2>/dev/null; then
    path_profile_action="already_configured"
    return 0
  fi
  ensure_path_profile "$profile" "$line"
  path_profile_action="added"
}
```

安装成功 JSON 写入 `path_profile_action`。自定义安装跳过时只向 stderr 输出当前进程可用的 PATH 指引。
