# v0.3 AO 真实试运行与 v0.4 规划实施计划

> **AIAgent 执行要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务实施本计划。步骤使用勾选框（`- [ ]`）跟踪。

**目标：** 收敛 GitHub Free 软门禁与源码发布的权威事实，使用已发布 v0.3 和真实 AO 工作项在 `agentic-ops` 工程完成一次受控端到端试运行，并把试运行证据转化为 v0.4 改进计划。

**架构：** 使用同一张 AO `Agentic 缺陷`工作项串联三个阶段。第一阶段的真实工作负载是修正文档、决策记录和计划状态；第二阶段由独立安装的 v0.3 AgenticCLI 完成真实 Jira 接管、证据、PR 和任务清理；第三阶段只根据本次运行事件和人工反馈形成 v0.4 设计与实施计划，不自动修改运行规范。

**技术栈：** Go 1.x、Bash、Git、GitHub CLI、Jira Cloud REST API、AgenticCLI v0.3、Markdown、YAML、JSON。

## 全局约束

- GitHub 组织套餐保持 Free，仓库保持私有；不再把升级 GitHub 套餐作为后续计划。
- `main` 的服务器端直推限制不可用是已接受风险；文档必须区分本地软门禁与 GitHub 服务端硬门禁。
- 日常开发目标分支为 `develop`；不得直接推送 `main`。
- 试运行代码工程固定为 `tapstate/agentic-ops`，工作空间固定为 `ao`。
- 所有 Jira 人可见标题、描述、评论、证据和决策使用中文。
- 真实 Jira 创建、字段写入、评论和状态转换分别停在明确人工确认点，不批量推定授权。
- Git commit、push、创建 PR、合并和任务完成清理继续保留人工门禁。
- Jira 工作项创建成功后，以返回的实际 key 作为 `AO_ISSUE_KEY`；所有提交都绑定该 key。
- 工作分支使用 `harsen/${AO_ISSUE_KEY}/develop`，从最新 `origin/develop` 创建。
- 不提交 token、cookie、私钥、临时安装目录、原始 Jira 响应或未经脱敏的日志。
- GitHub PR 使用 Merge commit；本阶段 PR 目标为 `develop`，不触发源码发布和 Tag 操作。
