# 归档恢复依赖描述

所属模块为 `workflow.task_handoff`。格式版本由模块 `FORMAT` 维护，当前 `agenticops-handoff-v2`；版本随接续材料要求变化，不随应用 epoch 变化。任务状态读取与保存使用 task_store 接口，Git 源码核验复用 station_source，不建立第二份任务库或 Jira 客户端。

`prepare` 从 Agent 核实的方案、进度、剩余事项、环境要求和必要材料回读生成正文；任务身份与代码基线、远端分支和 Head 来自现役任务及 Git。`verify_readback` 核对原生 Jira 工具回读的对象与正文。`continuation_input` 提供现役接管所需代码引用。`restore` 在当前任务中记录经过核验的成果来源，项目业务字段、授权和阶段继续由原功能检查；跨工位恢复不读取旧工位、旧缓存或本地快照。

v2 的 evidence 是对象列表：持久 `reference`、原生 `source_ref`、内容 `sha256` 和 `size_bytes`。生成和恢复时传入 Agent 原生取回文件的 local_file，模块读取核对字节，不持久化本机路径或内容。链接文本不证明可取回；回读来源真实性由 Agent 核实。可再生缓存不要求归档。无法保全的必要材料先披露并取得研发决定，不能谎报可恢复。

v1 正文仍可提取代码引用；无必要材料时也可接回方案。v1 仅有文本证据引用时不能证明内容一致：Agent 从项目取回材料、核实变化并与研发确认后，依据当前描述整理新正文，原生保存到 Jira 并回读后作为新的有效接续点（不要求旧工位可用）；不改写历史评论，不新增逐版本迁移器。格式未知或字段缺失时依据本描述和可信事实补齐，不能只改版本号、伪造进度或验证。

多次归档保留历史，Agent 依据 Jira 有效决定与远端事实选择接续点；程序不按时间擅自覆盖决定。当前远端 Head 已前进时先核实新增成果，不能为了匹配旧点回退分支。新工位接回的 handoff_resume 随任务清理，不影响远端持久成果；本地快照是可选副本。重复相同 restore 返回已保存状态，不代表之后所有业务事实仍有效，继续操作仍走正常功能检查。
