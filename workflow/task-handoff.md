# 归档恢复依赖描述

所属模块为 `workflow.task_handoff`。格式版本由模块 `FORMAT` 维护，当前 `agenticops-handoff-v3`；版本随接续材料要求变化，不随应用 epoch 变化。任务状态读取与保存使用 task_store 接口，Git 源码核验复用 station_source，不建立第二份任务库或 Jira 客户端。

v3 保存完整工程的仓库引用。工作区干净且 Head 等于冻结 SHA 的仓库为 `disposition=baseline`，无需推送空工作分支；生成时用临时空对象库从远端精确取回该 SHA，失败不开始归档。对应 continuation 只含 `baseline_sha`，接管时重新从远端取回并冻结该提交，不追随源分支的新 Head，不建立开发绑定。其余已登记改动继续使用 `retained` 的工作分支、历史基线和预期 Head，必须精确回读远端工作分支；合并后分支已删除的改动不自动改用目标分支，须按可信 Git/Jira 事实整理有效成果引用。未登记仓库偏离基线仍拒绝，明确放弃仍使用 `discarded`。旧 v1/v2 正文继续按原引用接续，不凭空补造未记录仓库的历史版本；新变体须使用支持它的安装，不改变已有持久状态意义或 epoch。

TapData 逐线修复归档可携带已回读的 `repair_line`。已验收合并的仓库以 `disposition=merged` 保存 PR 和合并事实，临时空仓库分别核验候选 Head 和合并提交可取回，候选 Head 可从精确 PR Head 恢复。换线接管按下一目标重新冻结完整工程，`restore` 校验新主仓目标后只接回已合并的事实和剩余事项。旧候选及其 PASS、授权不转入下一线；源码清理仍核验独有成果，源分支删除时仅识别与已核验 PR Head 完全相同的工作分支。

`prepare` 从 Agent 核实的方案、进度、剩余事项、环境要求和必要材料回读生成正文；任务身份与代码基线、远端分支和 Head 来自现役任务及 Git。`verify_readback` 核对原生 Jira 工具回读的对象与正文。`continuation_input` 提供现役接管所需代码引用。`restore` 在当前任务中记录经过核验的成果来源，项目业务字段、授权和阶段继续由原功能检查；跨工位恢复不读取旧工位、旧缓存或本地快照。

v2 的 evidence 是对象列表：持久 `reference`、原生 `source_ref`、内容 `sha256` 和 `size_bytes`。生成和恢复时传入 Agent 原生取回文件的 local_file，模块读取核对字节，不持久化本机路径或内容。链接文本不证明可取回；回读来源真实性由 Agent 核实。可再生缓存不要求归档。无法保全的必要材料先披露并取得研发决定，不能谎报可恢复。

v1 正文仍可提取代码引用；无必要材料时也可接回方案。v1 仅有文本证据引用时不能证明内容一致：Agent 从项目取回材料、核实变化并与研发确认后，依据当前描述整理新正文，原生保存到 Jira 并回读后作为新的有效接续点（不要求旧工位可用）；不改写历史评论，不新增逐版本迁移器。格式未知或字段缺失时依据本描述和可信事实补齐，不能只改版本号、伪造进度或验证。

多次归档保留历史，Agent 依据 Jira 有效决定与远端事实选择接续点；程序不按时间擅自覆盖决定。当前远端 Head 已前进时先核实新增成果，不能为了匹配旧点回退分支。新工位接回的 handoff_resume 随任务清理，不影响远端持久成果；本地快照是可选副本。重复相同 restore 返回已保存状态，不代表之后所有业务事实仍有效，继续操作仍走正常功能检查。
