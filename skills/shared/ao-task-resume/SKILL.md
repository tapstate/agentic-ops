# 从 Jira 接续任务

先核验工位项目及 Product Root，按[任务接续指引](../../../docs/usage/task-authorization.md#从-jira-任务接续)读取当前规则。用户给出 Jira key 即可开始，不先索要旧 run、备份路径或整段聊天。

## 核验与补全

从 Jira 当前任务、相关评论及链接读取有效目标、设计、验收、最新决定和进展；沿 GitHub 分支/PR/提交/CI 核验实际代码与报告。确认历史基线与完整 Head，避免把最新目标或推算的 merge-base 当原起点。核对本地占用、未完成操作及外部未知结果，依[更新与回退](../../../docs/usage/update-and-rollback.md#任务处理中升级后继续)处理旧现场，不用目标版本读旧 epoch 状态。

已完成成果继续复用。缺项先从源码、Git/PR/CI 与可访问的旧材料可靠核实；仍无法确定的只询问关键输入并给出具体选项，区分事实、推测与新决定。用户已确认且仍适用的设计不重复确认；材料不全不等于全部重做，历史 PASS 也不等于当前通过。

## 接续与记录

兼容的原 run 沿原操作恢复；已经退出或重建的工位，使用当前项目接管 Skill 和现有 continuation-input/repository add 入口建立新 run，核验保留分支、历史基线与预期 Head，再按当前检查点记录方案、证据和有效授权。旧状态、授权及质量日志不导入，不手改阶段。

在方案、交付、验证和暂停节点更新现有 Jira 字段/评论与 GitHub 对象，保留来源、完整 SHA、环境依据、未覆盖范围和剩余工作。升级前核对尚未持久化的本地源码与报告，按有效授权保存并回读；没有推送或上传的成果明确保全位置和恢复限制。秘密只记录引用。临时脚本可以补齐历史记录，但不进入框架作为逐版本迁移器。

输出已复用成果、补齐决定、实际执行状态和下一项缺口，接回项目开发与环境验证。生成接管状态、安装成功或容器就绪不等于任务验收；具体执行与清理使用项目现役入口，本技能不增加授权或状态机。
